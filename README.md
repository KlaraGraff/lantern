## 你早就在用 AI 读书了，只是方式很别扭

读到一段看不懂的，复制，切窗口，粘进聊天框，问它。

它给了你一段回答——但它不知道你在读哪本书，不知道你读到第几章，不知道这句话前后写了什么，也不知道你的英语到什么程度，所以它默认按母语者的口径回答你。看完了，切回阅读器，刚才读到哪儿还得再找一遍。而它给的那个答案是悬空的：你想回去核对原文，只能自己翻。

**Lantern 是反过来做的。** 它是一款 macOS 和 Windows 上的桌面阅读器，本地优先，用你自己的 AI 服务。它不把书一段一段搬进聊天窗口，而是**把 AI 放进书里**——那些你懒得每次交代的事，它一开始就知道。

具体是四件事：

1. **它拿得到上下文**——你的英语水平、读到哪、在读哪一本哪一章、选中处前后是什么，都随每一次请求过去。
2. **它说的每一句都能点回原文**——给的不是一个孤零零的答案，而是能带你回到书里那一句的答案。
3. **它说什么、怎么说，由你写**——预设模块不合用，自己写提示词造一个。
4. **它甚至可以不是它**——通过 MCP 把书库和生词本交给 Claude Code、Codex，换成你自己惯用的 AI 来读。

## 一 · 它知道的，比一个聊天窗口多得多

一个通用聊天窗口拿到的只有你粘进去的那几行字。Lantern 每次请求带过去的，还有下面这些——**不需要你交代，也不需要你重复交代**：

| 它知道 | 于是 |
| --- | --- |
| 你的英语水平 | 解释的用词和句子复杂度跟着变，而不是永远按母语者的口径来 |
| 你读到哪 | 默认不拿你还没读到的地方来回答你 |
| 你在读哪一本、哪一章 | 认得出书里的人名、地名和前情，不用你每次说「这是《XX》里的」 |
| 选中处前后是什么 | 先定住这个词在这里的意思，再展开——而不是罗列一堆词典义项让你自己挑 |
| 整本书 | 答案是从书里检索出来的，不是靠模型对这本书的记忆 |

### 它知道你的水平

大多数阅读工具的「英语解释」是一个开关：打开，就给你一段接近母语者的英文。对 B1 的读者来说，这段解释本身就是新的障碍。

Lantern 把英语水平当作**每一次请求的条件**，而不是界面上的一个偏好。你可以在个人资料里直接填 CEFR 等级（A1–C2），也可以填雅思、托福、托业、剑桥英语、DET 或四六级成绩，由应用换算成学习等级。

| 你的等级 | AI 怎么解释 |
| --- | --- |
| **A1–A2** | 以准确的中文义为基础，配一句符合当前水平的简明英文。不会「用更难的英文解释简单英文」。 |
| **B1** | 以英文解释为主；抽象的、容易误解的部分保留必要的中文辅助。 |
| **B2–C2** | 提供更自然、更深入的英语解释，需要时再展示目标语言翻译。 |

不过「照顾水平」很容易滑向另一个毛病：为了简单而牺牲准确，把精确的词换成含糊的词。所以这里还有一条硬规矩——**解释里如果非用一个超出你水平的词不可，那就保留它，并且当场就地加注**，用几个更简单的英文词或一个中文括注说清楚。**不许换成更含糊的词，也不许扔在那儿让你另外去查。**

选「英语优先」因此不等于接受看不懂的母语级解释——解释本身也是**可理解的输入**。你可以从「先看懂」开始，慢慢过渡到「用英语理解英语」，而不必被一段读不懂的英文再打断一次。

### 它知道你读到哪

**它默认不会拿你还没读到的地方来回答你。** 一旦提前知道后面发生了什么，你的思路会不自觉地朝那个方向收拢——你本来会自己琢磨出来的东西，就没有机会出现了。

所以「阅读思考保护」把回答限制在你已经读过的范围内，答案上标明「已按你的阅读进度回答（前 X%）」。等你确实想要完整的答案，点一下「结合全书重新回答」。这个开关可以按书单独设。

要它看多大范围也由你定：自动、只看选区、只看本章、或者全书检索。

## 二 · 它说的每一句，都能点回原文

开始读一章之前，你可以先让它把这一章里你可能不认识的词和短语列出来。它给你的是一份长清单——而清单里的每一条后面都跟着一个角标，**点一下，书就翻到那个词所在的那一句**。

读到一半想问剧情也一样。它不会甩给你一个答案就完了，而是把依据一起给出来，每条依据同样是可以点的。

这不是「回答下面附一个参考列表」。做这件事最好的产品是 NotebookLM，但它的引用只能跳到侧栏里的一段文本——**Lantern 本身就是阅读器，所以引用跳回的是书里真正的那一页、那一句**，落点还会闪一下，告诉你眼睛该看哪。

具体怎么工作：

- **引用是内联的。** 回答正文里直接带角标，回答末尾再列成一排，两处都能点。一次生词清单引用三十几处也不会乱。
- **定位是按原文找的，不是按页码猜的。** EPUB 拿原文片段在对应章节里精确搜索，找不到就换一个备用片段，再不行退到章节开头；PDF 跳到对应页；纯文本按字符偏移直接定位。
- **答案是从书里检索出来的**，不是靠模型记忆。全书建了全文索引，配了 embedding 服务的话还会叠一层语义检索——所以冷门书、新书和你自己的文档，它一样答得准。
- **而且它受上一节那些约束。** 引用不会来自你还没读到的地方，检索范围也听你的——所以「读之前列生词」这件事才成立：它扫的是你即将读的这一章，不是整本书。

### 隔了几天回来，那段对话还挂在书上

聊天软件里的历史记录是一条越堆越长的流水：你三天前问的那个句子，混在报销流程和菜谱中间，翻回去找不到，找到了也想不起来当时读到哪。

Lantern 的每一段对话都按书归好了类，可以搜，能看到是几天前问的、聊了多少条。找到当时那一段，点「**在阅读器中打开**」——书打开了，**那段对话也跟着回到侧栏**，你接着上次的话头继续问。对话里那些角标依然是活的，点一下照样跳回书里那一句。

所以不只是「每一句能点回原文」，是**整段对话本身就长在书上**。

## 三 · 预设模块只是起点，工具应该由你来造

一张查词卡上该出现什么？语境含义、词性、常见义项、搭配、词根词缀、语法角色、近义词、用法、记忆提示、原句出处——Lantern 内置了这些模块，单词卡 11 个、短语卡 8 个、段落卡 9 个，每一个都能单独开关、排序、设默认展开状态和内容密度。

**但预设不该限定你的学习方法。**

如果现有模块不够用，你可以自己造一个 AI 模块：

- 给模块起名字，写**完全属于你自己的提示词**（最长 2000 字）。
- 让它基于当前选区、上下文和书籍信息生成内容。
- 把它加进单词、短语或段落卡片，和内置模块一起显示、隐藏、排序、设展开。
- 在设置里即时预览卡片结构；确认要看真实效果时，再调用一次真正的 AI。
- 每种卡片最多 8 个自定义模块，另外还能建 6 个自定义选区操作，绑快捷键或双击触发。

比如你可以做出这些：

- 面向雅思或考研的**长难句拆解**模块；
- 用于文学作品的**修辞、叙事视角与语气**模块；
- 用于专业书籍的**术语、前置知识与应用场景**模块；
- 用于写作积累的**可复用表达与改写建议**模块；
- 只保留最少信息、不打断沉浸阅读的**极简查词**模块。

## 四 · 换成你自己的 AI，也行

前面三节讲的都是「Lantern 把上下文给了它内置的 AI」。但那些上下文凭什么只有它自己能用？

Lantern 内置了一个 **MCP 服务器**。打开它，Claude Code、Codex 这些 AI 客户端就能直接读你的阅读数据——**你不用复制粘贴任何东西**：

| 它们能读到 | 具体是什么 |
| --- | --- |
| 你的书库 | 书目、合集、元数据、书的正文与分块索引状态 |
| 你的语言档案 | CEFR 等级和你填的雅思 / 托福等成绩——**和内置 AI 用的是同一份** |
| 你的学习记录 | 生词本、掌握状态、统计、查询历史、词形标记 |
| 你留下的东西 | 高亮、书签、笔记、书内对话历史、章节摘要 |

一共 29 个工具。默认只读；**写权限（导入书、删书、建合集这些）是一个单独的开关，默认关着**——把数据交出去和把控制权交出去是两回事，不该捆在一起。

于是你可以在终端里直接问：「按我的英语水平，从我书库里挑三本能读下去的」「把我这个月标为『学习中』的词整理成一份带例句的清单」。它读的是你真实的阅读记录，不是你临时描述给它听的版本。

## 五 · 每一处都能改，而默认值已经替你想过

前面几节里的解释口径、检索范围、卡片模块，其实都是同一件事的不同侧面：**Lantern 里几乎没有写死的地方。** 颜色、样式、模块、快捷键、朗读音源、卡片上显示什么、选中文字后弹出什么——能调的都能调。

但「什么都能调」如果意味着「你得先调完才能用」，那只是把活推给了你。所以每一项都有默认值，而且这些默认值是认真想过的：装上就能直接读，只在你觉得哪里不顺手的时候，才需要去动它。

正文标记是这两点体现得最集中的地方。

### 标记：两套样式，六个维度

**手动标记**和**查词自动标记**是两套完全独立的样式，各有颜色、透明度、高亮 / 下划线 / 加粗、字体六个维度。想让两者长得一样，有一个「跟随手动标记」的开关。

默认值不是随手定的：手动标记是暖黄实底——那是你自己标的，就该显眼；自动标记是很淡的褐色加下划线——那是查词留下的痕迹，应该能一眼读过去。两者靠**形状**而不只是颜色区分，所以永远不会认错。

- **加粗和换字体默认关闭。** 因为它们会改变文字宽度：在分页模式下，一个标记出现就会让这一页重新排版，换行位置和页边界跟着变。颜色、背景、下划线不会移动任何文字。想要就打开，但你得先知道代价。
- **应用自己也在正文上画东西**：朗读到的位置是一层冷蓝的洗色，生词 / 学习中 / 已掌握是三档下划线——从暖橙到青再到灰色虚线，是一条「注意力逐步撤走」的渐变，不是四种互不相干的颜色。
- **所以选色时它会拦你一下**：如果你挑的颜色和上面这些太接近，设置里会当场提示「正文里可能分不清」，并指出撞的是哪一个。这个判断是把两个颜色**在真实纸底上混合之后**再算色距，不是比 HEX——一个洗色和一条下划线在色板上离得远，铺到纸上可能就分不开了。预设色也是按「离系统标记最远」挑的，但预设只降低概率，色号输入框和取色盘照样接受任何颜色。

### 词形标记：标记的是一个词，不是一串字符

你在书里查了 `run`。这本书后面出现的是 `ran`、`running`、`runs`——按字符匹配，它们和 `run` 毫无关系，一个都不会被标记。但对读者来说，它们本来就是同一个词。

所以「标记单词时」有三档，不是两档：

| 选项 | 行为 |
| --- | --- |
| 仅标记当前位置 | 只标这一处 |
| 标记本书中的相同单词 | 标全书所有拼写完全一样的 |
| **同单词各词形** | 标全书这个词的**所有词形** |

**词形不需要你手动录入。** 词形管理器里每个已标记的单词旁边有一个按钮，点一下就让 AI 生成它的词形；也可以一键批量补全所有还没有词形的词（10 个一批、5 路并发、失败自动重试一次、随时可取消，带进度）。

生成完还能改——你觉得 AI 漏了或者给多了，直接在输入框里编辑。手动改过的会被记成你自己的版本，不会被后续的批量生成覆盖。

### 别处也是一样的

- **朗读音源**默认「自动」：查一个词用词典的真人录音，读一整段用神经语音，两者都失败退回系统语音。但四种音源你都可以直接指定。
- **书籍来源站点**是一份可以随便增删的清单，不是固定名单。
- **三击选中什么**、快捷键怎么绑、要不要在选区菜单里显示快捷键——都是设置项。
- **学习卡片的内容密度**有一个说明弹窗，逐个模块告诉你「简洁 / 标准 / 详细」各自会多出什么，让你知道自己在选什么。

## 三分钟上手

1. **下载安装** —— 从 [Releases](https://github.com/KlaraGraff/lantern/releases) 取对应平台的安装包。macOS 首次打开时 Gatekeeper 会要求确认（原因见[下载](#下载)）。
2. **填一个 AI 服务** —— 打开「设置 → AI 服务」，填 OpenAI 兼容 API、Anthropic、Ollama 或自建网关，测试连接。密钥只存在这台设备上。
3. **拖一本书进来** —— 把 EPUB / PDF / TXT 拖进书库，打开它，**双击任意一个单词**。

想让它更贴合自己：去「设置 → 个人资料」填英语等级，去「设置 → 卡片设计」调你想看的模块。

## 支持的格式

| 格式 | 导入方式 | 阅读控制 | 选择与手动高亮 | 自动词汇标记 |
| --- | --- | --- | --- | --- |
| **EPUB** | 原生阅读 | 字体、行距、页边距、滚动 / 分页 | ✅ | ✅ |
| **TXT · Markdown · HTML** | 保留原文件，转换为稳定的内部 EPUB | 同 EPUB | ✅ | ✅ |
| **PDF** | 原生阅读 | 主题、缩放、单页 / 双页、滚动 / 分页 | 有可用文本层时 ✅ | ❌ |
| **MOBI · AZW · AZW3 · FB2 · FBZ** | 通过 Foliate 原生解析器 | 渲染器支持时可用流式控制 | ❌ | ❌ |
| **CBZ** | 原生阅读 | 仅主题 | ❌ | ❌ |

以上描述的是当前的本地导入与阅读器集成能力。不支持 DRM，也不保证完美渲染每一种出版商特定的文件变体。

## 你的数据在哪

- **书库数据本地优先。** 书、阅读进度、生词本、笔记都存在这台设备上。
- **API Key 与 OAuth 令牌只保存在本机的凭据数据库里**，不会返回给界面层，也不参与同步。
- **需要多设备同步时**，在设置里选一个你自己 iCloud Drive 里的文件夹，每台 Mac 选同一个。应用把事件日志、书籍和封面放在那里。当前版本不使用原版 Quill 的 iCloud 容器，也不宣称与原版 Quill 的 iOS 应用或其私有 iCloud 数据兼容。
- **AI 请求默认只发送完成当前任务所需的上下文**，不会自动上传整本书。

## 开发

要求：Node.js 22、npm、Rust，以及目标平台的 Tauri 前置依赖。阅读器引擎（foliate-js）源码已随仓库提交。

```bash
git clone https://github.com/KlaraGraff/lantern.git
cd lantern
npm ci
npm run tauri dev
```

常用静态检查：

```bash
npm exec tsc --noEmit
npm run lint
cd src-tauri && cargo check
```

技术栈：Tauri 2 + Rust + SQLite（后端），React 19 + TypeScript + Tailwind 4（前端），foliate-js（EPUB 渲染）。仓库协作约定见 [AGENTS.md](AGENTS.md)。
