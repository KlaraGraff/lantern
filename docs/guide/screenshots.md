# 产品截图：镜头清单与拍摄方式

README 和后续推广共用同一批截图。这份文档定义**每一张图必须证明什么**；怎么拍是脚本的事。

## 怎么拍

```bash
node scripts/shoot-readme.mjs                    # 全部
node scripts/shoot-readme.mjs hero coverage      # 只拍这两张
node scripts/shoot-readme.mjs --out=/tmp/shots   # 试拍，别脏了仓库
```

图不是画的，也不是手拍的。脚本启动 `npm run smoke`——**真实的 React 前端 + 真实的 foliate-js，只有 Tauri 那一侧是 mock**——把界面驱动到指定状态，等页面自己说就位（`data-shot-ready`），再用 CDP 截图。

这套做法的全部意义是：**应用渲染不出来的效果，图上就不会有。** 宣传图和产品之间不留缝。

三条纪律：

- **不要用图像模型生成界面。** 生成的按钮和文字一眼假，砸的是产品可信度。
- **不要手动 `⌘⇧4` 补拍。** 手拍的图带着当时的本机数据和窗口尺寸，换一版就对不上，也没法重拍。脚本每次拍出来一样。
- **图里的书必须是公版书。** README 是公开的。样张书架是 Standard Ebooks 的 12 本（`harness/promo/library.ts`），全部美国公有领域，封面用的也是公有领域画作。

### 三个文件

| 文件 | 管什么 |
| --- | --- |
| `scripts/shoot-readme.mjs` | 镜头表：`name`（输出文件名，**必须和 README 里 `![](…)` 引的一致**）、`scene`、窗口尺寸 |
| `harness/promo/index.ts` | 每个场景的设置项和落地路由 |
| `harness/promo/scenes.ts` | 把界面点到该有的样子，就位后打 `data-shot-ready` |

场景是**点出来的**，不是塞状态塞出来的：点侧栏、双击正文里的词、点工具栏按钮——读者怎么走，脚本就怎么走。找元素按 `src/i18n/zh.json` 里的可见文案或 `aria-label` 匹配，**不往 `src/` 里加 `data-testid`**——harness 的硬规矩是「`src/` 里没有任何东西知道 harness 存在」。

### AI 生成的内容怎么办

截图脚本里不能有 API Key，所以卡片和回答里的 AI 文本由 `harness/invoke-fixtures.ts` 的样张分支给出。规矩：

- **结构必须是应用真会渲染的结构**（`LearningCardResult` / 对话消息 / 引用），不是另画一套版式。
- **例句只能取自那 12 本公版书**，而且要真出现在书里——图会被放大读。
- **不编数字。** 覆盖率、词数、章节数这些要么从样张书架真算得出来，要么不出现。

## 这批图要说的是什么

README 的主张是**「把 AI 放进书里，而不是把书搬进聊天窗口」**——差异点是 AI 一开始就拿得到的那些上下文：你的英语水平、你想要什么样的解释、读到哪、在读哪一本哪一章、选中处前后写了什么、整本书的检索结果。

「上下文」是个抽象词，**唯一能让它落地的办法，是让画面里同时出现「AI 的输出」和「它凭什么这么输出」**：解释旁边要有等级，答案下面要有进度提示和原文来源，清单条目旁边要有能点回去的角标，画像卡片旁边要有依据。

所以每一张图都要能回答「**它凭什么知道**」，而不只是「它能做什么」。

## 镜头清单

九张，顺序就是 README 里的顺序。

### 1. `hero` —— 首图

**位置**：README 顶部。**场景**：`hero`。

阅读器全景，三样东西同框：左侧正文（暖色纸底，一段读得下去的英文，别停在章节标题或空白页）、中间浮在正文上的查词卡（选一个语境义和字面义不同的词）、右侧展开的 AI 侧栏，里面有一轮已完成的对话。

**判据**：0.5 秒内说清「这是个什么软件」。**侧栏那轮回答里必须看得到引用角标和底部的「来源」一行**——这是和「又一个 AI 阅读器」拉开距离的地方。三块都不能空，但正文仍应是画面里面积最大的部分。

### 2. `level` —— 它知道你的水平

**位置**：第一节「它知道你的水平」。**场景**：`levels`。

同一个词在两档水平下的两张查词卡并排。左边偏中文义 + 简明英文，右边是自然的英语解释。选一个中等难度、义项多的词，两边差异要肉眼可见。

**判据**：如果两张卡里能出现「**保留难词并就地加注**」的例子（一个超出等级的词后面跟着括号里的简单解释），优先选那一对——README 专门讲了这条规矩，有图佐证最好。

### 3. `profile` —— 它知道你想要什么样的解释（新）

**位置**：第一节「它知道你想要什么样的解释」。**场景**：`profile`。

用户画像页：上半段用户自己写的那几行，下半段七个维度里的三四张系统卡片，**其中一张展开着「依据」**。

**判据**：这张图的主角是那段展开的依据。它说的不是「AI 会揣摩你」，而是「**它把凭什么这么判断摊开给你看，而且你随时能推翻**」。画面里最好同时有「移动到上段」这类动作入口——它说明冲突时以你写的为准。

### 4. `context` —— 它知道你读到哪

**位置**：第一节末尾。**场景**：`context`。**这批图里最重要的一张。**

AI 侧栏特写（可以裁掉大部分正文，留一点边缘表明它长在阅读器里），同框四样：

1. **回答范围选择器**，展开更好，四档（自动 / 选区 / 本章 / 全书）可见。
2. **阅读思考保护开关**，处于打开状态。
3. **一条回答**，问题必须**明显指向全书**（「结局是什么」这类）——只有这样下面那条提示和按钮才会出现。
4. 回答下方那组元信息：「已按你的阅读进度回答（前 X%）」、旁边的「**结合全书重新回答**」按钮、以及原文来源标注。

**判据**：传达的不是「AI 能回答问题」，是「**它知道你读到哪，主动没有越界，并且把这件事告诉了你**」。那个「结合全书重新回答」尤其重要——说明这不是能力不足，是刻意的克制，而且随时可以解除。进度百分比落在 30%–50%：太低像没读，太高体现不出「后面还有一大截」。

### 5. `citations` —— 可点击的原文引用

**位置**：第二节。**场景**：`citations`。

左右两半：左边 AI 侧栏里一份长生词清单，**每条后面都带角标**，末尾还有一排来源芯片；右边是点了其中一个角标之后的正文页，**被引用的那一句正在高亮**。

**判据**：两边的对应关系要一眼可见，读者会去核对。清单要够长，让人看到滚动条——「一次引用三十几处」这件事本身就是说服力。

### 6. `mastery` —— 掌握度是读出来的

**位置**：第三节「掌握度不是你打的卡」。**场景**：`vocab`。

生词详情里的掌握度时间线：哪一天、在哪本书、跨了几天读到几次没查、哪一次复习评成了什么，以及卡上那个「**我其实不认识**」。

**判据**：主角是时间线本身——它证明这个档位不是系统随口给的，是有来由的，而且**你一按就能推翻**。四档的名字要拍准：新词 / 学习中 / 眼熟 / **读顺了**。

### 7. `coverage` —— 这本书对你（新）

**位置**：第三节「这本书对你难不难」。**场景**：`coverage`。

书籍详情页的「这本书对你」：覆盖率落在那把带 95% / 98% 两条参考线的尺子上，展开的词次构成（读顺了 / 眼熟 / 人名地名 / 还不认识），以及「**哪些词认下来提升最大**」那一段。

**判据**：数字必须是样张书架真算得出来的。这张图说的是「**本机就能回答这本书对你难不难，不联网、不花 AI 额度**」——如果画面里能同时看到那句本地计算的说明，更好。

### 8. `modules` —— 自定义模块

**位置**：第四节。**场景**：`cards`。

设置 → 划词与卡片：自定义模块编辑器，**提示词输入框里有真实内容**（比如「把这个长句拆成主句和从句，标出每个从句的作用，用中文说明」），别留占位符；旁边的模块列表能看到内置和自定义混排、可排序、有开关。

**判据**：传达的是「这个软件我能改」。提示词框里的文字是重点，确保清晰可读。

### 9. `mcp` —— 换成你自己的 AI

**位置**：第五节。**场景**：`mcp`。

左右两半：左边设置 → MCP，**Claude Code 的开关打开、「允许写入权限」关着**——这个对比就是这一节的论点（把数据交出去和把控制权交出去是两回事），别拍成两个都开；右边一个终端，Claude Code 正在回答一个只有读到真实数据才答得出的问题，推荐「按我的英语水平，从我书库里挑三本能读下去的」。

**判据**：右边那个回答是全部说服力所在。**回答里必须真的报出样张书架上那几本书的书名和 CEFR 等级**；如果只有一句「好的，我来看看」，这张图就废了。终端字号调大——社交平台缩略之后终端文字最先糊。

## 备用镜头（不进 README，推广用）

拍法相同，`scripts/shoot-readme.mjs` 的 `EXTRA_SHOTS` 里加一行即可。

- **`library`** —— 书架网格，封面丰满，左侧书单展开有内容。已可拍。
- **`wordforms`** —— 上半是「标记单词时」的三档下拉（选中「同单词各词形」）和词形管理器里的真实数据；下半是同一页正文里 `ran` / `running` / `runs` 都带着标记。**说服力全在下半**：上半只讲「有这个选项」，下半才讲「它真的标到了不同词形」。
- **`markers`** —— 标记样式区，实时预览那行示例里同时出现朗读洗色和三档下划线，并且**故意触发一次撞色警告**。警告文案是主角：传达的不是「功能多」，是「这软件替你想过」。
- **`qa`** —— 问答列表按书分组，条目上带「3 天前 / 7 天前」。**信息是时间**，别裁掉。切入点是「和 AI 聊过的东西不会丢在聊天软件里」。
- **`reading`** —— 不带任何弹窗和侧栏的纯阅读画面。用来反驳「AI 阅读器都很吵」，也适合做推广图背景。

## 交付与自查

输出到 `assets/screenshots/<name>.png`（2x）。README 里九处图片路径已经写好，但**被 HTML 注释包着**——图没拍完就露出来是一排碎图标。图放进去之后，把每处注释的首尾两行删掉即可。

- [ ] 侧栏显示的是 "Lantern"
- [ ] 画面里没有任何真实 API Key、邮箱、账号，MCP 配置里也没有真实用户名或本机绝对路径
- [ ] 书全部是公版书，封面也是
- [ ] 术语拍的是当前版本：读顺了（不是「已掌握」）、笔记 / 问答（不是「标注」「对话」）、书单（不是「合集」）、AI 配置（不是「AI 服务」）
- [ ] `hero` 的回答里看得到引用角标
- [ ] `context` 里同时有进度提示和「结合全书重新回答」
- [ ] `profile` 里有一张卡展开着依据
- [ ] `coverage` 里的数字是真算出来的
- [ ] `mcp` 右边终端真的列出了书名，不是客套话
- [ ] 文字在 100% 缩放下清晰可读
