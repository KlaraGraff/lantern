# 截图拍摄指南

README 和后续推广共用同一批截图。这份文档是拍摄规范和镜头清单，文末附一段可直接交给另一个 AI 助手（或人）执行的提示词。

**重要前提：这些是真实软件界面的截图，必须由真正运行起来的 Lantern 产出。** 不要用图像模型生成界面——生成出来的按钮、文字和布局一眼就能看出是假的，会直接损害产品可信度。图像模型只用来做推广物料的背景板和封面，不用来做界面。

## 这批图要说的是什么

README 的主张是**「把 AI 放进书里，而不是把书搬进聊天窗口」**——差异点是 AI 一开始就拿得到的那些上下文：你的英语水平、读到哪、在读哪一本哪一章、选中处前后写了什么、整本书的检索结果。

这句话直接决定了怎么拍。「上下文」是个抽象词，**唯一能让它落地的办法，是让画面里同时出现「AI 的输出」和「它凭什么这么输出」**：解释旁边要有等级、答案下面要有进度提示和原文来源、清单条目旁边要有能点回去的角标。只拍一张漂亮的查词卡，说的还是「这是个查词工具」。

所以每一张图都要能回答「它凭什么知道」，而不只是「它能做什么」。

## 现状

`assets/home.png` 和 `assets/reader.png` 是旧图：侧栏还写着 "Quill"，用的是旧的紫色配色，和当前版本（v2.6.0）对不上。这批新图拍好后，README 里被注释掉的图片路径就能启用，旧图可以删掉。

## 环境准备

1. 在 `~/vibecoding/Lantern` 里跑 `npm run tauri dev`（或直接用已安装的 Release 版本，更接近用户看到的样子）。
2. **书库准备 12–15 本书**，让书架看起来是真在用的，不是空的。
   - **优先用公版书**（Project Gutenberg 上的 *Pride and Prejudice*、*Frankenstein*、*Moby-Dick*、*Walden*、*Alice's Adventures in Wonderland* 等）。推广图会被大量转发，用在版书的封面有版权风险。
   - 混一点中文书和不同类型的封面，让书架有视觉层次。
   - 建 3–5 个合集文件夹（Fiction、History、Sci-Fi……），并且让每个都有书。
3. **至少有一本书要「真的在读」**：阅读进度停在 30%–50% 之间，有若干高亮、几个生词、一段已有的对话历史。Shot 2、Shot 7、Shot 11 都依赖这些真实痕迹——空数据拍出来一眼假。Shot 11 还需要**这本书下面已经积了十几段隔了几天的对话**，这个攒不出来，得是真用过。
4. **给主力那本书建好索引**（设置或索引管理里可以看到状态）。没有索引，全书检索和引用角标都出不来。
5. **设置项**：
   - 界面语言：中文和英文各拍一套（英文那套给 `README.en.md` 用）。
   - 阅读主题：暖色纸感（默认主题），不要深色——深色截图在社交平台的白底信息流里会糊成一块。
   - 个人资料里的英语等级：拍 Shot 3 时需要在 A2 和 C1 之间切换。
   - 「设置 → AI」里的**阅读思考保护打开**（拍 Shot 2 需要）。
   - 「设置 → MCP」里的 **Claude Code CLI 开关打开、写入权限保持关闭**（拍 Shot 6 需要，且这两个状态本身就是那张图要说的话）。
6. **必须清理的**：
   - 任何真实 API Key、邮箱、账号名。设置页截图前把 Key 字段留空或换成明显的假值（`sk-••••••••`）。
   - **MCP 配置 JSON 里如果有本机绝对路径**（`/Users/<你的用户名>/…`），把用户名涂掉或换成 `you`。
   - 桌面通知、其他应用的窗口、系统托盘里的私人信息。

## 拍摄规范

| 项目 | 要求 |
| --- | --- |
| 窗口尺寸 | 1440 × 960（应用默认值，见 `src-tauri/tauri.conf.json`） |
| 分辨率 | Retina 屏拍摄，实际输出 2880 × 1920 |
| 格式 | PNG |
| 截图方式 | macOS 上 `⌘⇧4` 然后按空格选窗口，会自动带上窗口圆角和阴影 |
| 背景 | 纯色或极浅的渐变，不要拍到桌面壁纸 |
| 文件大小 | 单张压到 500 KB 以内（用 ImageOptim 或 `pngquant`），README 里 6 张图加起来别超过 2.5 MB |

## 镜头清单

按顺序拍，文件名严格对应，直接放进 `assets/screenshots/`。前六张进 README，各自对应一节；后面几张是备用和推广用。

### 1. `hero.png` —— 首图，最重要的一张

**位置**：README 顶部。

**内容**：阅读器全景，三样东西同时在画面里：

- 左侧：正文，暖色纸底，一段读起来舒服的英文段落（不要停在章节标题或空白页）。
- 中间：一张查词卡浮在正文上，词选得要有代表性——一个语境里含义和字面义不同的词最好。卡片上要能看到语境含义、简短中文义、英文定义。
- 右侧：AI 对话侧栏展开，里面有一轮已完成的对话。

**要点**：这张图要在 0.5 秒内说清「这是个什么软件」。**侧栏那轮回答里必须能看到引用角标和底部的「来源」一行**——这是首图和「又一个 AI 阅读器」拉开距离的地方，别拍一段光秃秃的文字。三个区域都不能空，但也别让侧栏挤掉正文——正文仍然应该是画面里面积最大的部分。

### 2. `context.png` —— 它知道你读到哪（新增，这批图里最重要的一张）

**位置**：第一节「它知道的，比一个聊天窗口多得多」的末尾。

**内容**：AI 侧栏的特写（可以裁掉大部分正文，只留一点边缘表明它长在阅读器里），画面里必须同时有这四样：

1. **回答范围选择器**，显示成「回答范围·自动」——点开让下拉展开更好，四档（自动 / 选区 / 本章 / 全书）都可见。
2. **阅读思考保护的开关**，处于打开状态（打开时是强调色的）。
3. **一条回答**，问的是一个明显指向全书的问题——**「结局是什么」「总结全书」这类**。这一点是硬要求：只有当问题本身指向全书时，下面那条提示和按钮才会出现。
4. **回答下方的那一组元信息**：「已按你的阅读进度回答（前 X%）」这条提示、旁边的**「结合全书重新回答」按钮**，以及「当前阅读范围原文」这个来源标注。

**要点**：这张图是整个新定位的证据。它要传达的不是「AI 能回答问题」，而是**「它知道你读到哪，并且主动没有越界，同时把这件事告诉了你」**。那个「结合全书重新回答」的按钮尤其重要——它说明这不是能力不足，是刻意的克制，而且随时可以解除。

进度百分比最好落在 30%–50%，太低像没读，太高就体现不出「后面还有一大截没告诉你」。

### 3. `level.png` —— 它知道你的水平

**位置**：第一节的「它知道你的水平」小节。

**内容**：同一个单词在两个等级下的两张查词卡，**并排拼在一起**（用任意图片工具左右拼接，中间留 40px 白缝）：

- 左边标注 `A2`：中文义为主 + 简明英文。
- 右边标注 `C1`：自然的英语解释。

选词建议：选一个中等难度、义项多的词（`giggle`、`grunt`、`sprawl`、`peculiar` 这类），两边差异要肉眼可见。

**可选加分**：在拼图上方放一小条「个人资料 → 英语等级」的设置行截图，说明这个差异是从哪来的。**如果两张卡里恰好出现了「保留难词并就地加注」的例子**（一个超出等级的词后面跟着括号里的简单解释），优先选那一对——README 专门讲了这条规矩，有图佐证最好。

### 4. `citations.png` —— 可点击的原文引用

**位置**：第二节「它说的每一句，都能点回原文」。

**内容**：左右拼接（中间留 40px 白缝），左边是 AI 侧栏，右边是点击之后的正文：

- **左边**：一轮已完成的对话，问的是「把这一章我可能不认识的词和短语列出来」。回答是一份清单，**每一条后面都带着一个角标**（`S1` `S2` `S3`……），回答末尾还有一排来源芯片。清单要足够长，让人看到滚动条——「一次引用三十几处」这件事本身就是说服力。
- **右边**：点了其中一个角标之后的正文页，**被引用的那一句正处在高亮闪烁状态**。左边被点的那一条和右边高亮的那一句，内容要对得上，读者会去核对。

**要点**：这张图讲的是「联动」，所以两边的对应关系必须一眼可见。可以在两边之间画一个箭头，或者把左边被点的那一条和右边高亮的那一句用同一个颜色框出来。**闪烁高亮是转瞬即逝的，可能要多截几次才能抓到**——如果实在抓不到，用录屏截帧。

### 5. `modules.png` —— 自定义模块

**位置**：第三节「预设模块只是起点」。

**内容**：设置 → 卡片设计，画面里要同时有：

- 自定义模块编辑器，**提示词输入框里有真实内容**——写一个具体的、看得懂的提示词，比如「把这个长句拆成主句和从句，标出每个从句的作用，用中文说明」。别留占位符文字。
- 模块列表，能看到内置模块和自定义模块混排、可拖动排序、有开关。

**要点**：这张图要传达的是「这个软件我能改」。提示词框里的文字是重点，确保它清晰可读。

### 6. `mcp.png` —— 换成你自己的 AI（新增）

**位置**：第四节「换成你自己的 AI，也行」。

**内容**：左右拼接，左边 Lantern，右边终端：

- **左边**：设置 → MCP 页面。**Claude Code CLI 的开关是打开的，「允许写入权限」的开关是关着的**——这两个状态的对比就是这一节的论点（把数据交出去和把控制权交出去是两回事），别拍成两个都开。
- **右边**：一个终端窗口，Claude Code 正在回答一个只有读到真实数据才答得出的问题。推荐问：**「按我的英语水平，从我书库里挑三本能读下去的」**——回答里要能看到它真的报出了你书库里那几本书的名字和你的 CEFR 等级。

**要点**：右边那个回答是全部说服力所在。如果回答里只有一句「好的，我来看看」，这张图就废了——等它把书名列出来再截。终端字号调大一点，社交平台上缩略之后终端文字是最先糊掉的。

**注意**：截之前先确认 MCP 配置 JSON 里的绝对路径不带你的真实用户名。

### 7. `wordforms.png` —— 词形标记（备用，README 未引用）

**内容**：两部分拼在一起（上下拼接，中间留 40px 白缝）：

- **上半**：设置 → 标记，「标记单词时」的下拉展开，三个选项都可见，选中的是「同单词各词形」；下面展开的词形管理器里有几行真实数据（`run` → `ran, running, runs, run's`），其中一行正在转圈生成。
- **下半**：正文截图，同一页里 `ran`、`running`、`runs` 三个不同词形**都带着标记**。这一半是重点——它证明设置真的生效了。

**要点**：这张图的说服力全在下半部分。上半只讲「有这个选项」，下半才讲「它真的能标到不同词形」。正文里最好能同时看到三种以上词形。推广选题里这是单独一条，值得拍。

### 8. `markers.png` —— 标记样式与撞色警告（备用）

**内容**：设置 → 标记的样式区，画面里要有：

- 手动 / 自动两套样式的切换，和六个维度的控件（颜色、透明度、高亮 / 下划线 / 加粗、字体）。
- **实时预览那一行示例文字**，里面同时出现朗读洗色、生词 / 学习中 / 已掌握三档下划线、手动标记和自动标记。
- **触发一次撞色警告**：故意把颜色调到接近某个系统标记，让「这个颜色和下面的标记太接近」那行提示出现在画面里。

**要点**：警告文案是这张图的主角。它传达的不是「功能多」，而是「这软件替你想过」。

### 9. `library.png` —— 书库（备用）

**内容**：书架网格视图，封面丰满，左侧合集文件夹展开有内容。给推广图用。

### 10. `reading.png` —— 纯净阅读（备用）

**内容**：不带任何弹窗和侧栏的纯阅读画面，暖色纸底，衬线正文。用来反驳「AI 阅读器都很吵」这个印象，也适合做推广图的背景。

### 11. `chats.png` —— 对话按书归档（备用，推广用）

**内容**：左右拼接，讲的是「几天前那段对话还挂在书上」：

- **左边**：「对话」列表页。按书分组，每条能看到标题、消息条数和「3 天前 / 7 天前」这样的时间。**列表要够长**——十几条真实对话本身就说明「这不是个演示数据」。上方的搜索框和书籍筛选芯片要在画面里。
- **右边**：点进其中一条的详情页，右上角的「**在阅读器中打开**」按钮要清晰可见（可以加个箭头指它）。

**要点**：这张图的信息是**时间**——「3 天前」「7 天前」这些标记是全部说服力所在，别裁掉。理想的第三格是点了按钮之后的阅读器画面：书打开了，那段对话回到了侧栏；但拼三格在手机上会太挤，做成 GIF 更好。

**推广用法**：这条适合做一条独立选题，切入点是「和 AI 聊过的东西不会丢在聊天软件里」——目标人群是技术 / AI 工具那一批，他们最有体感。
