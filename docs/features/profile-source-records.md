## Motivation

画像卡片上的「依据」行现在只有一句话，是总结器给出的**概括**，例如：

> **依据：** 近 90 天 412 次查词里，航海、历史类领域词占近四成，名词占六成，日常词几乎不查。

这句话本身是模型写的。读者要判断这张卡该不该信、该不该改，唯一能依靠的就是这句概括——而它恰恰是最需要被核对的那一环。「查看原始记录」把这条链补上：点开就能看到这条结论背后真正的那些查词、追问、标注。

样张（`docs/impls/user-profile-mockup.html:297`）里这个链接是画着的，功能没做。**链接留着就是一句承诺**，所以要么补上，要么把链接撤掉——不能长期停在画而不做的状态。

## Scope

In scope：

- 卡片「依据」行末尾的「查看原始记录」入口（样张已有位置，不新增版面）。
- 点开后展示这张卡所依据的原始条目：时间、来源（哪本书 / 哪次对话 / 哪条标注）、原文片段。
- 只读。这里不提供编辑或删除——要改结论走既有的「移动到上段修改」，要删走「删除」。
- 分页或截断：抽样上限是每维度 ≤ 5 条样本，但底层统计覆盖的条目可能上千，展示层要有明确的「看到的是抽样，不是全量」的说明，不能让读者以为这就是全部。
- i18n：zh / en 各自取词。

Out of scope：

- 从原始记录反向修改画像结论。
- 跨维度的全量记录浏览器（那是「阅读历程」的活）。
- 导出。

## 待解的设计问题（动工前要先出样张）

1. **展示形态**：卡片内就地展开，还是右侧抽屉，还是弹窗？条目数不定，就地展开会把下面的卡片推很远。
2. **「抽样 ≠ 全量」怎么说**：总结器读的是预聚合统计 + 每维度 ≤ 5 条加权抽样原文（见样张 606 行）。所以「原始记录」严格讲有两层——喂给模型的那 5 条，和统计覆盖的全部条目。给读者看哪一层，或者两层都给但分开标注，是个产品判断。
3. **记录已被删除时**：书删了、对话清了，依据还在，条目却取不出来了。空态怎么说。

## Implementation Phases

1. 后端查询命令：按卡片维度取回其依据条目（events 表查询），带分页。单测覆盖：条目存在、条目已被删除、维度无记录三种情况。
2. 展示界面：先出静态样张给用户看版式，确认后再写组件。
3. i18n + 走查：亮/暗双主题、空态、长列表。
