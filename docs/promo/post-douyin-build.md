# 抖音 · 第一条 —— 「我用 AI 写了一个英文阅读器」

对应 [推广方案](launch-plan.md) 选题 1。

**为什么抖音只能发这条。** 方案里那张平台表把抖音排在低优先级，理由是这个产品需要「看得懂界面」，而抖音的节奏不给人看界面的时间。这个判断没变——变的是**这条选题不靠界面成立**。它讲的是一个人做出一个东西的过程，界面只是证据。功能介绍在抖音发不动，做的过程发得动。

**发布前提**：正式版已发、能双击安装。**口播和字幕里不出现版本号。**

---

## 片长与结构

45 秒。竖版 1080×1920。口播 + 屏幕录像，人不用出镜。

抖音的默认观看条件是**静音、1.5 倍速、只看前三秒**。所以：字幕必须自成一套（关掉声音也能看完），第一句必须是结论不是铺垫。

## 那三个数字是真的

| 数字 | 出处 | 复算 |
| --- | --- | --- |
| 5 个月 | 首次提交 2026-03-06 | `git log --reverse --format=%ad --date=short \| head -1` |
| 1045 次提交 | 截至 2026-08-10 | `git rev-list --count HEAD` |
| 19 万行 | 前端 7.6 万（TS/TSX）+ Rust 11.2 万 | `git ls-files 'src/**/*.ts*' 'src-tauri/src/**/*.rs' \| xargs wc -l` |

**发之前重跑一遍，用当天的数字。** 这类内容的可信度全靠数字经得起问——评论区一定会有人问「多少行」「怎么算的」，答不上来比不发还糟。19 万行不含翻译文件和 vendor 目录，被问就这么说。

## 三条必须守的

**不交代自己的技术背景。** 口播、字幕、发布文案、评论区回复，一律不提。这条片子的说服力来自那三个数字和屏幕上真实跑起来的软件，不来自「作者是谁」——一旦交代了背景，评论区的话题就从产品转到人，而那是这类内容最常见的翻车点。

带 `#AI编程` `#vibecoding` 这些标签，一定会有人问「你是不是程序员 / 你会写代码吗」。**准备一句不接话的回法**，把话题推回作品：「代码全在 GitHub 上，可以直接看。」——不撒谎，也不展开。

**别念网址。** 抖音对站外导流敏感，口播和字幕里都不要出现 GitHub 地址，写在个人简介里，评论区置顶一句「主页」。

**录屏必须是真的应用。** 不许用样张脚本的浏览器画面冒充桌面应用，也不许剪掉加载过程假装秒出——流式生成本来就好看，等它两秒不丢人。

## 录屏怎么出

四段录屏在 [推广方案](launch-plan.md) 的 D 节里已经列了规格。这条片子要用到其中两段（双击查词、点角标跳原文），加上一段聊天窗口的对照录屏。

工具 Kap（免费，macOS）录 MP4，别导 GIF——这是视频不是 README。录之前把书库切成样张用的那批公版书，**别录到自己的真实书库**，也别让 API Key、邮箱、绝对路径出现在画面里，规矩和[镜头清单](../guide/screenshots.md)那份是同一套。
