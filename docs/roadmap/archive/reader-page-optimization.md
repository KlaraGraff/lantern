# 阅读页优化推荐方案

> 2026-08 调研汇总。方法：5 份代码现状分析（布局/交互/设置主题/面板/引擎能力）× 8 份外部调研（Apple Books、Kindle、微信读书、掌阅、多看、KOReader、Moon+ Reader、Anx Reader、Readest、Thorium、Calibre、Koodo、阅读 UX 研究、中英文用户吐槽）。
> 吐槽线只作对照检查，逐条判断值不值得改——发声的总是少数，全按意见改会丢掉占比最多的普通用户。
> 所有建议以产品方针为前提：安静、像书、工具退后于正文、AI 辅助但不打断阅读（见 `personalized-english-reader-master-plan.md`）。

> **状态（2026-08-06）：** 除 P3.5（双语对照整书翻译）外，P0、P1（7 项）、P2（5 项）、P3.1–P3.4 已全部落地并归档验收（见 `docs/impls/README.md` Archive 一节「Reader P2/P3 line, shipped and accepted」）。P3.5 的记录已带入 [`outstanding-work-audit-2026-08.md`](outstanding-work-audit-2026-08.md)。本文件作为历史规划记录归档，不再是待办清单。

## 一、已达标、应保持的底子

这些是调研中反复被别家用户抱怨、而 Lantern 已经做对的地方。优化时**不要动**，排版相关改动要用同一批样书前后对照（微信读书的教训：排版引擎牵一发动全身，他们每版都逐本截图回归）。

| 项 | 说明 |
|---|---|
| 正文行宽 34em 上限 | 阅读研究里证据最强的一条（西文 50–75 字符/行）恰好已内建（`reader-theme.ts` 常量）。宽窗口下不会拉成超长行 |
| 深色主题非纯黑 | 底色 `#151518`（`reader-theme.ts:106`），避开"夜间模式纯黑刺眼/光晕"这条中文区高频吐槽；自定义主题有 WCAG ≥4.5 自动文字色 |
| 翻页动画克制且可关 | none/slide/fade 可选，避开 Kindle page curl 强制拟物动画被迫补开关的反面教训 |
| TOC 一键直达 | 左侧常驻面板、当前章节自动展开、只在打开时抢一次滚动焦点——别家"目录藏三层菜单里"是中英文区共同吐槽点 |
| 跨页选择 | 拖到边缘续选（`reader-bindings.ts`），正是 Kobo/Apple Books 被骂"跨页高亮卡死"的地方 |
| 打开失败分级提示 | 15/30/45s 阶梯提示 + 卡住提示，别家是静默白屏 |
| 字体回退链 | 10 款 OFL 字体 + 中文回退链，双语书不崩排版 |
| 工具退后 | 独立窗口模式工具按钮常驻但弱化至 60% 透明度、hover 恢复，符合"工具退后于正文"的气质 |
| AI 语境查词 | 就地弹层 + 注入当前段落上下文。这是三方生态验证过的最大空白（微信读书生态封闭接不了词典、Thorium 内置词典 issue 五年未做、浏览器端靠沙拉查词等插件拼凑），是护城河，继续加深而不是加宽 |

## 二、推荐改进清单

### P0 — 缺陷与一致性修复（先清掉，无争议）

1. **word-spacing 单位分裂 bug**：同一个设置 key，阅读页面板按 `%`（−10~50）、设置页标成 `px`（−4~16），实际渲染按 `%`（`reader-theme.ts:154`）。统一为 %，改设置页标签和范围。
2. **charSpacing 补全局默认值**：它是唯一没有全局默认的排版项，行为和其他项不一致。
3. **设置页补齐 6 个缺失的全局项**：i18n 字符串已存在未用，属于 `docs/features/12-reader-settings-layers.md` stage 1 已规划未完成的部分。
4. **"cover" 翻页动画名不副实**：实际退化为 slide（`page-turn-transition.ts:129-131`），且 View Transitions 路径下三种动画全部退化（106-119）。要么修好，要么把该选项下架——挂着不生效的选项比没有更伤信任。
5. **归档 q260 spec**：文档还在描述旧版弹窗 TOC，代码已是常驻侧栏，按仓库约定移入 `archive/`；其中"TOC 展开状态是否持久化"这个未决问题单独带出（见 P1.7）。

### P1 — 低成本高价值：引擎/后端已有，接上即用

按建议实施顺序排列。

1. **脚注气泡弹层**。现状：`footnotes.js` 的 `FootnoteHandler` 躺在 `public/foliate-js/` 全仓零引用，点脚注整页跳走再手动翻回。EPUB3 标准做法（Kindle/Apple Books/新 Kobo 都是就近弹气泡），对读学术/技术书的用户是高频硬伤，且和"不打断阅读"方针完全同向。引擎代码已在仓库，成本主要在弹层 UI（可复用查词弹层的定位逻辑）。
2. **书内全文搜索**。现状：`view.search()`（异步生成器，返回带 CFI 的匹配+进度）只被 AI 引用跳转内部用过（`Reader.tsx:1069`），没有面向用户的搜索框。这是相对所有成熟阅读器最基础的缺失项，引擎已把难的部分做完。顺手加"搜索范围：全文 / 我的标注与生词"两档（KOReader 模式），后者对生词积累多了之后是真实需求。
3. **统一跳转历史 + 返回**。现状：foliate 内链跳转有 canGoBack 按钮但 10 秒后自动消失（`useFoliateView.ts:470-483`）；TOC、书签、高亮、AI 引用跳转全部单向无返回（`TableOfContents.tsx:163-174`、`flashNavigationTarget` 只闪 3 秒标记不回位）。做法：所有 `goTo` 入口统一压入历史栈，绑 `⌘[`/`Alt+←`（和浏览器一致零学习成本），返回按钮改为"有历史即显示"的克制样式，不再定时消失。AI 辅助阅读天然高频"跳出去看引用再回来"，这条对 Lantern 的价值高于普通阅读器。
4. **高亮备注与改色接上 UI**。现状：`updateNote`/`updateColor` 后端命令 + hook 已实现（`useBookmarks.ts:112-126`），全仓零调用，用户创建高亮后只能删除重建。在高亮弹层和面板里就地编辑；删除时区分"仅删备注 / 连高亮一起删"（Apple Books 的细节，成本≈0）。同时给 ExplainPopover/TranslationPopover 补上 LookupPopover 已有的收藏/追问入口，三个弹层能力对齐。
5. **剩余阅读时间 + 进度口径点击切换**。现状：全应用没有任何时间预估。Kindle 最有辨识度的功能（点击进度区循环：页码 → 本章剩余 N 分钟 → 全书剩余 → 关），微信读书也是"百分比+已读时长+预估剩余"三合一。实现纯本地统计：最近 N 次翻页速度 × 剩余字数。注意研究结论：剩余时间常驻会带来压迫感——所以做成点击切换的口径之一而非默认常驻，默认仍显示页码。
6. **进度条从显示条升级为可拖 scrubber + 章节刻度**。现状：1px 纯显示（`Reader.tsx:1890-1897`）。KOReader 的章节刻度线（TOC 节点位置打点，一眼看出本章还有多长）+ Anx Reader 的拖动方案（本地即时预览、100ms 防抖后真正跳转、300ms 后刷新）可以直接抄。悬停显示章节名。配合 P1.3 的历史栈，拖错了能一键回去。
7. **两个顺手小项**：TOC 展开状态按书持久化（现在每次开书都要重新展开）；用引擎的 `getTOCItemOf()` 替换自制 href 匹配（嵌套多级目录下当前章节判断更准）。

### P2 — 中等投入的体验补齐

1. **标注/生词结构化导出**。英文区高频吐槽第 3 名（导出难催生了 Readwise 一整个付费生态），KOReader 是正面标杆（Markdown/JSON/对接笔记服务）。Lantern 笔记已有 CSV 导出但入口在 Home；扩展到高亮和生词、加 Markdown 格式（含原文、前后文、章节、CFI、AI 释义、时间戳）、阅读页侧栏加入口。生词导出顺手做 Anki 兼容（CSV+说明即可起步）。
2. **生词复习语境化**。Kindle Vocabulary Builder 的核心是"复习卡正面显示书中原句"；Readest 同类需求（issue #789，12 赞）至今未做；掌阅"查词带本书例句"验证同一方向。Lantern 生词卡已存例句和书名，主要改复习呈现：语境句优先、原词挖空。这是 master-plan 核心循环"阅读→语境查词→追问→沉淀复习"最后一环的直接强化。
3. **排版补齐三项**：两端对齐开关 + 按书籍语言的连字符（CSS `hyphens:auto` + 正确 `lang`，浏览器原生支持，成本极低，英文书两端对齐的"文字河流"问题一次解决）；段落间距；首行缩进（中文书刚需，微信读书单独做成开关；缩进要学 Anx 的"智能跳过"——居中段、图片段不缩进）。范围学 Anx 做档位收口，防止用户拖出极端组合。
4. **每书覆盖的双向门**。现状是一旦某书改过设置就永久脱离全局、无提示无返回（`12-reader-settings-layers.md` stage 2 已规划）。做法采用 Readest 被社区认可的显式开关模式：面板上明示当前作用域，提供"恢复跟随全局"和"应用到全局"两个动作。
5. **整书连续朗读 + 自动翻页 + 统一播放条**。现状朗读只对选中文本生效，`ReadingPlaybackBar` 是边缘补丁（仅暂停/继续/停止）。扩展现有系统语音管线做整书连续朗读（跨段推进 + 自动翻页），播放条补上一句/下一句/语速；中英混排段落按语言自动切换语音（Readest 已验证，对双语书体验差异巨大）。引擎的 `tts.js`/Media Overlay 可评估是否替换自建管线，但不是前提。

### P3 — 战略方向（每项先写 impl 文档再动手）

1. **阅读统计**（`q27` 已规划、零实现）。架构直接参考 Readest issue #3155 的分层：会话追踪（idle 5 分钟暂停、<30 秒会话丢弃）→ 日/书聚合 → 统计页；视觉用 Anx 的"主题色不同透明度"热力图，契合低对比气质。**铁律：纯私人、无社交、无排行、无分享默认**——阅读时长外泄和强制社交是微信读书被骂最狠的两条。
2. **阅读页笔记面板**（`q14` 已规划、零实现）。现状记笔记必须切出到 Home，阅读流被打断。
3. **被动生词注释（Word Wise 方向）**。基于用户生词库判断"这个词对你是生词"，行内浅色小字极简释义、密度可调、点击展开完整讲解。比 Kindle 的出版商预标注更进一步（千人千面）。是已归档的 vocabulary-aware lookup 计划的自然延伸，长期差异化。
4. **AI 人物/术语卡（X-Ray 方向）**。Kindle 独门、Readest 社区有呼声（#2709）但没人做好。AI 讲解管线的自然延伸：选中人名/术语 → 出场位置列表 + 关系摘要。v1 用全文检索聚合上下文即可，不需要向量库。
5. **双语对照整书翻译**。Anx/Readest 都有（译文逐段嵌在原文下方而非替换）。与英语学习定位契合度最高的一项，但 token 成本、缓存策略、排版复杂度都需要单独评估。

## 三、吐槽对照检查表

原则：**有吐槽 ≠ 要改**。逐条判断，标注"沉默多数"视角。

| 别家被骂什么（频度） | Lantern 犯没犯 | 值不值得改 |
|---|---|---|
| 排版控制粗糙、只有字号（EN 高频） | 半犯：字号/行距/字重/边距/字距齐，缺对齐/段距/缩进 | 值得补三项（P2.3）。但"忽略出版方 CSS"是极客诉求，普通用户期待"出版方排的版本来就该好看"，不做一键剥离 |
| 高亮笔记导出难，催生 Readwise 生态（EN 高频） | 犯：高亮/生词无导出，笔记 CSV 藏在 Home | 值得改（P2.1），重度读者的"资产可迁移"心智已被坐实 |
| 页码/Location 不稳定、无法引用（中英文都高频） | 用页码+百分比，同样没有稳定引用锚点 | **不改页码体系**。学术引用是小众刚需，加"页码模式"开关对普通用户是纯负担；用剩余时间（P1.5）满足"还要读多久"这个大众版本的同类焦虑 |
| 目录藏得深、跳转繁琐（中英文都有） | 不犯：左侧常驻一键开关 | 保持；只补状态持久化（P1.7） |
| 跨页高亮卡死（Kobo/Apple Books） | 不犯：拖到边缘续选已实现 | 保持，回归测试盯住 |
| 夜间模式纯黑刺眼或太暗（CN 中频） | 不犯：#151518 柔和深色 | 保持 |
| 强制社交、阅读时长外泄（CN 最高频，微信读书） | 不犯：无社交 | 做统计（P3.1）时把"纯私人"当铁律，这是别人痛点反向送的定位礼物 |
| 翻页动画拖慢、不能关（Kindle page curl） | 不犯：可关可选 | 保持；但修 cover 名不副实（P0.4） |
| 桌面端是二等公民（Kindle for Mac 被骂"crude"） | 不犯：桌面优先 | 保持键盘快捷键覆盖优势 |
| 查词割裂要跳出 App（中英文都有） | 不犯：AI 就地弹层是最强项 | 继续加深语境注入，不加宽 |
| 沉浸模式缺失、UI 干扰（中频，多来自极客） | 半犯：工具栏常驻不自动隐藏，但已弱化 60% 透明度 | **暂不做全自动隐藏**。弱化已符合"安静"方针；全隐藏+悬停唤出（Anx 的 30px 边缘检测）记为候选，等真实用户反馈再决定 |
| 墨水屏字重发虚、断词算法可配（EN，MobileRead 极客圈） | 不适用 / 半适用 | 墨水屏项忽略；断词只做 CSS 原生开关（P2.3），不做可配置算法 |
| 划线符号要学教程才会用（CN，重度笔记用户） | 不犯：单一高亮+颜色 | 保持简单，不引入多种划线语义 |
| 改版后功能找不到、广告入侵（多看，版本节点爆发） | 不犯 | 流程教训：核心路径改版保持稳定，本方案全部是增量不动现有入口 |
| 稳定性：进度丢失、卡第一页（散见各家） | 未见报告 | 底线功能，SQLite WAL 已是正确架构；每次发版前用样书回归开书/进度/标注三件事 |

## 五、建议落地顺序

1. **一个小版本清完 P0**（全是修正，无设计争议）。
2. **P1 按序逐项小步提交**：脚注弹层 → 全文搜索 → 跳转返回 → 高亮备注 → 剩余时间 → scrubber+章节刻度 → 两个小项。每项独立可发布，做完阅读页就补齐了与成熟阅读器的基础差距。
3. **P2 优先做 1、2**（导出 + 语境复习），它们和 AI 学习定位协同最强；3、4、5 随后。
4. **P3 每项先立 impl 文档评估**，不并行超过一项。
