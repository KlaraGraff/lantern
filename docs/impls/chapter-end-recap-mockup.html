先说一句最重要的：这个东西已经存在了。 src/components/chapter-end-hint.ts 已经在正文末尾画了一条细线——「这一章你查了 N 个词。趁着还有印象，过一遍 →」， 外加一个悬停才出现的「不再显示」，以及阅读设置里的一个开关。 所以这份样张不是新建一个板块，是给这条已有的线补上它缺的那一半：点开之后就地看到那些词。

缺的为什么是这一半——现在这条线只有一个动作，而这个动作是离开这本书： navigate("/", { state: { openReview: true } }) 回首页开「回顾」板； 独立阅读器窗口更狠，直接 window.close()。 于是「可点可不点」在成本上并不成立：不点是零代价，点一下的代价是你正读着的书没了。 读者在章末真正想做的是顺手扫一眼，不是「合上书去工作区」。

这份样张的全部主张就一句：把那一下点击从「跳走」改成「就地展开」。 展开是可逆的、不离开书页、不改变阅读位置；真正要离开书的那一步挪到展开之后，并且明说它去哪。 形态一步不放大——依然是一条细线，不是卡片、不是面板、不是浮层。

3 收起态 —— 默认，也是绝大多数人唯一会看到的样子

4 展开态 —— 点开之后

7 一个真实的实现风险：分页模式下展开会不会把自己顶到下一页

这条线安装在 doc.body 末尾，分页模式下 foliate 用 CSS 多栏排版，所以展开使 body 变高，就可能多出一栏—— 读者点了「看看」，词却排到了下一页，屏幕上什么也没变。这是这个设计唯一会被真实用到的技术坑，写在这里以免实现时才发现。

不能这么修：把展开做成浮层。 浮层能绕开分栏，但那一瞬间它就不再是「正文末尾的一行小字」，而是一张盖在书上的卡片—— 违反「做小、不要那么明显」，也违反「不挡住继续读下一章」。形态优先于实现便利。
两条一起用：
① 展开高度封顶。词最多两行（4 个 chip + +N，就是 capPileChips 的现成上限）， 加来由句和链接各一行——整块最多 5 行、约 96px。这个高度在常见字号下多数时候塞得进当前栏的余量。
② 展开后把这一块滚回视野。展开的回调里触发一次重排，再把这条线的锚点重新 scrollToAnchor—— 即使它翻到了下一栏，读者看到的也是「页面翻了一下，词就在眼前」，而不是「点了没反应」。 这和 useFoliateAnnotations 里已有的重排时机是同一套机制，不新造。

顺带一条既有事实值得保留：没读到章末的人永远看不到这条线（它安装在 body 末尾，分页下只落在本节最后一页）。 这是特性不是缺口——「章末微复盘」的前提就是你确实读完了这一章。

10 改动清单：真要做的其实很少

这份设计刻意压到「在既有那条线上加一层展开」的规模。下面是它落地会碰到的全部东西， 没有新表、没有新后端命令、没有新组件目录。

动怎么动
chapter-end-hint.ts 收起/展开两态；展开的三段内容；触摸设备把「不再显示」挪进展开态。仍然是纯 DOM，无 React、无 Tauri——它跑在书页文档里。
useFoliateAnnotations.ts 现在那个循环只数词（lookupCount += 1）；改成顺手把词也收进数组。数据已经在手里——vocab 加 CFI 解析，同一次遍历，零额外查询。
i18n 新增：「看看」「收起」「在「回顾」里打开这一章」「已关闭…」。复用：reviewBoard.pile.recentChapterLookups.reason、reviewBoard.pile.moreChips。
旧键 reader.chapterEndHint.action（「趁着还有印象，过一遍 →」）退役。
review-piles.ts 只用不改：capPileChips 直接复用，保证两处词数上限永远一致。
设置 / 后端 不动。chapter_end_review_hint 键、设置行、review_piles.rs、任何 schema——一个字不改。
要你拍板的只有两点：
① 收起态动作词从「趁着还有印象，过一遍 →」改成「看看 ⌄」——即把这条线从「跳走」改成「就地展开」。这是整份设计的地基。
② 展开态不做复习动作（无对错按钮、不记分），只看词、只连去已有的回顾板。
