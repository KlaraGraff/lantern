# Home 的侧边栏在窄屏变成抽屉

> P2 第 2 项。样张：[`mobile-home-drawer-mockup.html`](mobile-home-drawer-mockup.html)（8 屏，含跟手中间态）。
> 地基（安全区、`touch:` 变体、断点约定）是 P2 第 1 项，见 [`responsive-foundation.md`](responsive-foundation.md)。

## 一句话

`Home` 左侧那根写死 224px 的栏，在 `< 768px` 时收成抽屉：默认不占位，从左边缘拉出来或点按钮展开。
≥768px 的样子一个像素都不许变。

## 为什么值得单独写一份计划

因为它有三个容易被做成「能用但是错的」的地方：

1. **抽屉不是一个开关。** 做成 `open ? translate-x-0 : -translate-x-full` 加一个 transition，功能上是对的，
   手感上是死的。跟手意味着拖拽期间抽屉位置和遮罩浓度都由手指位置驱动，只有松手那一下才交给动画。
2. **抽屉里要能上下滚，同时要能横向拖着关。** 同一块区域上两种手势，必须先做方向锁再决定归谁，
   否则用户想滚收藏夹却把抽屉关了。
3. **窄屏的判断和触摸的判断不是同一件事。** 拖窄的 macOS 窗口要拿到抽屉版式，但不该拿到 44px 热区和安全区留白。
   这条规矩在地基文档里，这里是它第一个真实的消费者。

## 范围

**做：**
- `src/components/Sidebar.tsx` — 内容不动，容器分叉：宽屏还是 `<aside>`，窄屏是抽屉里的同一份内容
- `src/pages/Home.tsx` — 顶栏加汉堡按钮（仅窄屏）、搜索框宽度、标题区
- 新增 `src/hooks/useDrawerGesture.ts` — 手势与吸附，纯逻辑，可单测
- 收藏夹行的触摸替代动作（行尾 `···` 菜单 + 「编辑」排序模式）
- `hasTitleBarInset` 第一次被真正读取
- i18n：新增键写进 `en.json` 和 `zh.json`，保持数量对等

**不做（属于别的项）：**
- 阅读器的任何东西（P2 第 3 项、P3）
- 查词/翻译弹窗改底部抽屉（P2 第 5 项）
- 设置面板（P2 第 4 项）
- 书籍下载中的状态（P2 第 8 项，样张第 5、6 屏画了但不在本次范围）
- 除本次触及组件外的任何写死宽度（P2 第 6 项）

## 断点与词汇

- **版式分界：`md:` = 768px。** 不新造断点名。
- 本次触及的组件转成 **mobile-first**：无前缀的类是窄屏，`md:` 前缀是桌面。
  没转的组件保持原样（无前缀 = 桌面），两种写法并存是过渡期的正常状态，不要顺手去改别的组件。
- **触摸相关一律 `touch:`**（`pointer: coarse`），绝不用宽度。
  热区尺寸、长按、点击反馈属于这一类。

## 结构

```
Home
├─ (md:) <aside> Sidebar            ← 今天的样子，不动
├─ (<md) <DrawerHost>
│    ├─ 遮罩 scrim                   ← 透明度 = 拉出比例
│    ├─ <aside> Sidebar             ← 同一个组件，同一份内容
│    └─ 左边缘 20px 起手区（不可见）
└─ <main>
     └─ 顶栏：(<md) 汉堡按钮 + 标题 + 视图切换
```

`Sidebar` 保持一个组件。它不知道自己在抽屉里还是在栏里——由外层容器决定位置，
它只需要在窄屏把行高从 36px 提到 44px（`h-11 md:h-9`）。
把它拆成两个组件是错的：内容会立刻开始分叉，以后往书库里加一行就要加两遍。

## 手势规格

常数抄 readest（见 `docs/roadmap/readest-comparison.md` §5），它们是调过的，不要自己拍：

| 项 | 值 | 作用 |
|---|---|---|
| 边缘起手区 | 屏幕左侧 20px | **只有**从这里起手才能拉开 |
| 方向锁阈值 | 纵向位移 8px | 超过就锁成滚动，本次手势不再考虑抽屉 |
| 横向优势比 | 1.5× | 横向位移要大于纵向的 1.5 倍才算拉抽屉 |
| 吸附位置阈值 | 50% | 松手时拉出过半 → 到底 |
| 吸附速度阈值 | 0.5 px/ms | 快速轻扫无视位置，按方向吸附 |
| 收起动画 | 200ms | 仅松手后；拖拽期间不加 transition |

- **打开**只认边缘起手。书架中间以后要留给别的横向手势，中间也能拉的话，
  以后每加一个手势都要跟它抢优先级。
- **关闭**不限起点：抽屉上任意位置左拖、点遮罩、点汉堡按钮，都关。误触代价只是关掉。
- 拖拽期间抽屉的 `transform` 由手指位置直接写，**不走 React state 的每帧重渲染**——
  用 ref + 直接改 style，或 `useSyncExternalStore`。每帧 setState 在低端设备上会掉帧。
- 遮罩的 `opacity` 与拉出比例线性绑定，同样直接写。

`useDrawerGesture` 只吃指针事件、吐出「当前拉出比例」和「松手后的目标态」，
不碰 DOM 结构——所以它能脱离浏览器单测，不需要真机。**已实现**，见
[`src/hooks/useDrawerGesture.ts`](../../src/hooks/useDrawerGesture.ts)，23 个单测。

### 接线时唯一容易做错的地方：什么时候 `setPointerCapture`

`onPointerDown` 返回 `true` 只表示「这根手指值得跟」，不表示「这是一次拖拽」。
抽屉打开时它对整个屏幕的按下都返回 `true`——包括点在侧边栏某一行上的那次点击。

**这时候不能立刻 capture。** 指针捕获会把后续的 `click` 重定向到捕获元素，
于是侧边栏里每一行都点不动了：手势没做错，但整个抽屉变成了一块死板。

正确的时机是**方向锁解开之后**，也就是 `getState().dragging` 第一次变成 `true` 时：

```tsx
onPointerMove={(e) => {
  drawer.onPointerMove(e);
  if (drawer.getState().dragging && !e.currentTarget.hasPointerCapture(e.pointerId)) {
    e.currentTarget.setPointerCapture(e.pointerId);
  }
}}
```

在那之前手指还没离开起手元素，事件本来就冒泡得到，不捕获也收得到。
一旦判定成拖拽，手指会横穿整个屏幕，这时才必须捕获。

## 收藏夹的触摸替代动作

桌面上改名/删除靠右键，排序靠拖手柄。触摸上两者都没有对应动作。

- **改名 / 删除** → 行尾一个 `···` 按钮（仅 `touch:` 显示），点出同一个菜单。
  不用长按：长按已经许给阅读器里的查词了，同一个手势在两个地方含义不同会互相干扰。
- **排序** → 「收藏夹」标题右侧加「编辑」，进入后每行左侧出现手柄，此时才允许拖动。
  平时不允许拖，避免和抽屉的横向手势、列表的纵向滚动三方打架。

宽屏保持右键和拖手柄不变。

## 标题栏

`Sidebar` 和 `Home` 都有 `h-titlebar`（44px）的 `data-tauri-drag-region` 占位，
给 macOS 红绿灯让位。手机上没有红绿灯，这 44px 是纯浪费。

这是 `platform.hasTitleBarInset` 第一个真正的消费者——它至今没有被任何组件读取过。
读它，为假时不渲染那块占位、去掉 `pt-titlebar`。

**注意**：这一条按平台走，不按宽度走。拖窄的 macOS 窗口仍然有红绿灯，仍然需要让位。

## 无障碍与键盘

抽屉打开时：焦点移入抽屉并锁在里面，`Esc` 关闭，关闭后焦点回到汉堡按钮。
遮罩 `aria-hidden`，抽屉 `role="dialog" aria-modal="true"`。
背景内容 `inert`（Safari 17+ 支持；若不可用则退回 `aria-hidden` + 焦点锁）。

带键盘的 iPad 是常见配置，所以键盘路径不是可选项。

## 验收

1. `npm run lint`、`npm run test:unit`、`npm run build`、`npm run check:docs` 全绿
2. `useDrawerGesture` 的单测覆盖：方向锁、优势比、位置吸附、速度吸附、边缘起手拒绝非边缘起手
3. **回归基准：≥768px 的 Home 与改动前逐像素一致。** 任何可见变化都是 bug，不是改进。

   **验证方式不是截图对比。** 原本写的是「改动前后各截一张 1280px 截图」，
   但这个应用在普通浏览器里跑不起来——`useWindowSizePersistence` 第一行就读 Tauri 的
   window metadata，没有 Tauri runtime 时整个 App 在挂载阶段就抛异常，
   截到的是一张空白页。给 vite dev server 补一层 `invoke` mock 才能截，
   那是另一个项目（书籍、设置、收藏夹全都要造数据），本次不做。

   替代方案更强，不是更弱：**逐行证明**。要求 diff 满足下面三条，
   满足了就等价于像素一致，而且是证明，不是抽样：
   - `<aside>` 分支渲染出的 class 字符串和 inline style，在 ≥768px 下与改动前**逐字符相同**；
   - 每一个新增的 class 要么带 `md:` 前缀并且取值等于改动前的无前缀值，
     要么它所在的元素在 ≥768px 下根本不渲染；
   - 每一个新增的 DOM 节点（汉堡按钮、遮罩、起手区）在 ≥768px 下不渲染，
     或者渲染成零尺寸且不参与布局流。

   由一个独立的 reviewer 子代理按这三条审 diff，逐条给出结论。
4. 375px 宽度下：无横向滚动，抽屉能开能关，所有可点元素 ≥44px
5. 桌面浏览器把窗口从 1280px 拖到 375px，版式切换处不出现破版

第 3 条是这份计划里最硬的一条。这次改动的价值全在「手机能用」，
一旦桌面被顺手改了样子，成本就从「加一个平台」变成「两个平台一起返工」。

## 实现记录（已完成）

改动落在 `src/pages/Home.tsx`、`src/components/Sidebar.tsx`、两个 i18n 文件，
外加一个新的守卫测试 `tests/mobile-home-drawer.test.ts`（7 条）。

### 计划留白处的取舍

- **窄屏判断走 JS，不走 `hidden md:flex` 一对容器。** 两个容器装的是同一个组件，
  只能挂载一个：挂两份就是两份重命名/新建/拖拽状态，右键菜单会开在看不见的那份里。
  用 `useSyncExternalStore` + `matchMedia("(min-width: 48rem)")` 问的是和样式表同一个问题，
  两者不可能对不上。副作用是验收第 3 条第三点变成字面成立——≥768px 时抽屉的节点根本不存在。
- **指针事件挂在 Home 根 `<div>` 上**（且仅窄屏挂）。挂在 20px 起手区上不行：
  鼠标拖拽在跨过 8px 判定阈值之前就离开了那条 20px，事件会丢。根节点是所有东西的祖先，
  冒泡一定收得到，而控制器本来就会拒绝不属于它的指针。
- **热区尺寸用 `touch:`，行高用 `md:`。** 计划第 61 行明确写了行高是 `h-11 md:h-9`（跟宽度），
  样张第 7 屏写的是热区跟输入方式。两条都照做了：行高 `md:`，
  汉堡 / `···` / 「编辑」/ `+` / 右键菜单项一律 `touch:`。
- **「编辑」按钮做成标题行的兄弟节点，没有包一层 `<div>`。** 包一层就是在 ≥768px 新增了一个
  DOM 节点，撞验收第 3 条第三点。`hidden touch:inline-flex` 在鼠标下是 `display: none`，
  压根不是 flex item，`justify-between` 的标题行原样不动。
- **手柄在触摸下是隐藏而不是禁用。** `display: none` 同时把它从命中测试里拿掉，
  这才是 `handlePointerDown` 里那句 `closest("[data-grip]")` 在触摸上永远不会命中的原因。
- **`h-dvh` 是唯一一处改掉的无前缀类。** 没有动态浏览器 chrome 的平台上 `100dvh ≡ 100vh`，
  所以桌面的计算值不变。

### 没做的三处，以及原因

1. **搜索框在手机上仍是 36px 高**（样张画的是 40px）。高度在 `src/components/ui/Input.tsx` 里，
   那个文件不在本次可改范围内。宽度已经改了（`w-full md:w-[448px]`）。
2. **汉堡按钮只出现在书架那一支。** 生词、复习、对话、笔记四个视图各自渲染自己的顶栏，
   都在本次范围外的组件里。在那几个 tab 上，重新打开抽屉只能靠左边缘上滑手势。
   这四个顶栏应当在各自的项里补按钮。
3. **`hasTitleBarInset` 为假时不再渲染 44px 占位，这对 Windows / Linux 是可见变化。**
   `titleBarStyle: "Overlay"` 只配了 macOS，所以那 44px 在 Windows / Linux 上一直是纯浪费；
   按计划第 127 行「读它，为假时不渲染」执行。但它确实动到了一个在发的桌面目标，
   记在这里而不是当成无事发生。

### 守卫测试盯的是什么

`tests/mobile-home-drawer.test.ts` 钉住四类会静默失效的东西：桌面 `<aside>` 的类字符串逐字符不变、
`setPointerCapture` 必须被 `getState().dragging` 守着、指针路径上不许出现 `preventDefault`、
标题栏占位只许问平台不许问宽度。
