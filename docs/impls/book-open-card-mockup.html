开书卡 · 样张

它解决什么。今天点开一本书，进阅读器之前系统一句话都不说。这本书对你是轻松还是吃力、词汇难在哪一段频段、最吃力的一章在哪、比你读完的那几本重还是轻——全都要读进去几十页才知道。开书卡把这些放在打开之前。

只给一个粗的量级，不给精确数字。卡上关于「难」的说法只有一句：陌生词约占篇幅百分之几，取整到个位。不写「有 N 个生词」，不写「每 N 个词 1 个」，也不预测你会查多少次词——那是把一次翻开书变成一场考前估分。要看拆解的人可以展开「这个数字怎么来的」，但收起态永远只有一句话。

数据从哪来。两侧相乘。一侧是 book_difficulty：导入时把全书正文按 word_frequency 的五个频段 + 一个「表里没有」桶做过一次分布统计。另一侧是你自己的记录：lookup_records（你停下来查过的词）和 reading_word_exposures（在屏幕上出现过、你却读了过去的词），按频段折算成实证通过率。两者按频段逐段相乘再相加，就是这本书里陌生词占篇幅的比例。

为什么零成本。全部是本地表查表：频段表是随包的 5 万词 TSV，通过率来自本机 SQLite，分布在导入时已经算完并存进 book_difficulty。这条链上没有任何一次网络请求，也不经过 AI——开书卡打开时只是读几张表再做一次乘加，毫秒级。

它必须能关掉，而且是三层。每张卡右上角有 ✕（这次不看）；卡里有「不再显示开书卡」（整个功能不再出现）；设置里有同一个开关。中间那一层和设置里那一行是同一个状态，不是两个互不知情的开关。见第 7 节，含关掉之后开书流程长什么样。

顺手一起解决的。扫描件 PDF 的前置判定。今天是你点了 AI 功能才弹错，其实这本书在导入时算难度就已经撞到过 PDF_TEXT_LAYER_UNAVAILABLE——那一刻就知道它没有文字层。开书卡把这件事挪到打开之前说清楚。

样张里的每个数字都标了出处，见最后一节《数字从哪来》；查证后确认拿不到、因此没有画的指标也列在那里。 「难点集中在哪一章」已获批做 schema 变更，逐章难度由后端另行落库，本样张只定它怎么呈现（第 6 节）。

为什么是中间层，而不是首页卡片。首页是扫视场景，一个需要解释的百分比塞进封面下方会变成噪音；更实际的问题是它对「还没分析过 / 太短 / 格式不支持」的书是空的，网格会参差不齐。而这张卡要回答的问题本来就只在「我现在要打开它」那一刻成立。
为什么不是详情页。详情页要多点一次才到，而「打开之前什么都不知道」正是要治的病——治法不能是「你应该先去别的页面看看」。详情页那张卡继续存在，开书卡是它的摘要版，不是第二套数据。
为什么要有条件。开书是高频动作，每次都拦一下就是收税。出现条件只有三条：这本书从没打开过（status = 'unread'）；它是没有文字层的扫描件（阻断性事实，必须说）；或者书变了（重新导入 / OCR 跑完，stale = true）。其余情况——你正在读的书——降级成一条可折叠的细条，不挡路（见第 5 节）。

7关掉它 · 三层，以及关掉之后

开书卡是一个会在你没请求的时候出现的东西，所以它必须能关，而且要在它出现的那一刻就能关，不能让人去设置里找。 三层：✕（这次不看）、「不再显示开书卡」（整个功能不再出现）、设置里的开关。 后两者是同一个状态——卡里点掉，设置里那一行随即变成关；设置里打开，卡就回来。不存在「我明明关过了它怎么还在」这种局面。
措辞规矩：不挽留。没有确认弹窗，没有「你将失去…」，没有「确定吗」。点了就关，给一次撤销，说一句去哪儿再打开，完。

8数字从哪来 · 以及砍掉了什么

样张里每一处说法都对应现有的表和字段，唯一的新数据源是逐章难度（已批准的 schema 变更，后端另行落库）。下面是逐项对照，然后是查证后确认拿不到、因此没画的指标。
注意一条贯穿全卡的口径：库里的精度和卡上的精度不是一回事。下面这些字段都是精确值，卡上一律取整到个位并加「约」——精度是算出来的，可信度不是，把 3.1% 印在卡上等于替一次估算背书。

卡上的说法来自怎么算 · 怎么显示
词频构成（那条彩条） book_difficulty.band1…band5, band_unlisted, total_tokens 导入时全文分词后逐词查 5 万词频率表，落进六个桶。条的宽度用精确值，图例只标频段名不标数值；展开态里才给「约 78%」这种取整数。
你的实证通过率（展开态，约 99 / 96 / 86 / 70 / 52%） reading_word_exposures + lookup_records 按频段：读过两次以上且从没查过的词数 ÷（该数 + 查过的词数）。口径与 level_observation.rs 的 passed_by_band / looked_up_words_by_band 完全一致。显示时取整。
「没见过的词约占篇幅 3%」 上面两行相乘 Σ（该频段占篇幅 × (1 − 该频段通过率)），band 1–5，「表里没有」桶不参与。四舍五入到整数百分点；不取倒数，不换算成「每 N 词 1 个」，不换算成词数。
「比你读完的那几本略重一些」 book_difficulty（全库） (band4 + band5) ÷ total_tokens 与基线（已读完且统计过的书的平均值）比。两条阈值（至少 2 本、差 2 个百分点才算有差别）是 difficulty-view.ts 里已经在用的 MIN_BASELINE_BOOKS / VERDICT_MARGIN。只出方向，不出两个百分比——阈值判定本来就是三值的（轻 / 差不多 / 重），把中间量印出来只会引出「那 2.4% 是怎么来的」。

砍不画的指标

分两类：拿不到（数据源里根本没有），和拿得到但不画（是设计决定）。第二类现在多了两条——具体词数和查词次数预测，即使将来算得出来也不画。

「这本书里有 N 个你不认识的词」（一个具体词数）
两重否决。第一重，拿不到。要得到这个数，需要每个频段各有多少个不同词形。book_difficulty 只存了一个总的 distinct_words，六个桶存的是出现次数不是词形数。 用「出现次数的比例」乘「按词形算的通过率」能得到篇幅占比（那是有意义的量），但反推不出词数。
第二重，就算算得出来也不画。一个具体词数会被当成一道待办题读——「这本书要我认 1400 个新词」是一句能让人合上书的话。卡上一律说「约占篇幅 3%」，一个量级，不是一份清单。
「每 N 个词里有 1 个生词」（比值）
算得出来，不画。它就是那个百分比的倒数，不含任何新信息，但读起来完全不同：百分比是一个属性，「每 32 个词 1 个」是一段节奏——它让人开始在句子里数词，把阅读变成计数。同一个事实，换个写法就成了负担，那就用不成负担的那个写法。
「预计你会查 N 次词」
拿不到，而且是个不同的量，而且不该有。同一个生词在书里出现十次，占十个词的篇幅，你只查一次；从篇幅占比推查词次数需要知道生词的重复分布，库里没有。 更要紧的是它把一个观察写成了一个预言——预言会变成指标，指标会让人为了压低它而不去查词。卡上任何位置都不出现这个说法，连「这不是查词次数」这样的澄清也不出现：要澄清就得先把那个概念说出口。
两个百分比的直接对比（「4.6% vs 平均 2.4%」）
算得出来，只出方向。最近读完的那一本是拿得到的（books.status = 'finished' 排序），全库平均也是（difficulty-view.ts 的口径，至少 2 本）。 但阈值判定本来就只有三个结果（轻 / 差不多 / 重），把中间那两个百分比印出来，读者得到的不是更多信息，是两个需要自己再比一次的数。卡上只说「略重一些」，并点名一本读过的书当参照物——参照物比数字好用，因为你知道那本书读起来什么感觉。
统计进度百分比
拿不到。spawn_computation 只在结束时发一次事件，中途不报进度。第 4 节因此用不确定态占位，没有进度条——这跟第 3 节的 OCR 不同，那边 pagesDone / pagesTotal 是真的。
CEFR 等级标签（「这本书是 B2」）
不做，是设计决定不是数据限制。book_difficulty 的模块注释写得很清楚：结论就是那个分布，套一个等级标签是对它的有损压缩。 而且 book_difficulty 明文承诺永不改写 language_assessments 和任何设置——这张卡也不写，它只读。
