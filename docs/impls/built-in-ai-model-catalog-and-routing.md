# 内置 AI 模型目录与自动路由交接

已与用户对齐（2026-08-02）。本文是实现交接，不对应 GitHub Issue。

> **2026-08-02 修订：撤掉内置免费模型，改为主推 DeepSeek。**
> 用真实 Key 实测下来，智谱 GLM-4.7-Flash 的参数量不足以支撑本产品的核心用途——语法拆解和词义辨析会给出看起来像样、实际错误的输出，直接误导正在学英语的读者。一个会说错话的免费默认模型比没有默认模型更糟。
> 受影响的是 §1、§1.1、§2.2、§6.1、Phase 1 和 §11，均已按新目录改写。**§3、§5、§8 保持原样**：它们记录的是连接流程和路由行为的推导过程，其中的路由语义已由 Phase 3 的测试锁住，与本次目录改动无关；§3 与 §8.2 里的智谱字样此后只作历史记录读。

## 1. 结论

Lantern 不内置共享 API Key，也不把不受控的第三方免费接口仓库作为运行时配置源。产品提供一个由 Lantern 维护的**内置模型目录**，普通用户从中选择模型、按引导连接自己的服务商账号，然后把已连接模型加入一个可排序的**调用路由**。

首版默认推荐 DeepSeek，且不内置任何免费模型：

| 项目 | 值 |
| --- | --- |
| 用户可见名称 | DeepSeek |
| 服务商 | DeepSeek 开放平台 |
| 默认模型 | `deepseek-v4-flash`（可在界面里改成 `deepseek-v4-pro` 或任意模型 ID） |
| API Base URL | `https://api.deepseek.com`（不含版本段，由公共端点函数补 `/v1`） |
| API Key 页面 | `https://platform.deepseek.com/api_keys` |
| 费用标记 | 独立的“按量付费”标签，不写进名称；具体价格以服务商为准 |

名称按“服务商 · 模型”构成，不把价格写进名称。用户添加预设后名称会存进他自己的 Profile，而目录更新不允许改写已安装的 Profile（见 §4）；一旦服务商调整定价，写死在名称里的费用字样既改不掉又不再属实。费用信息只以独立标签存在，它属于目录元数据，可以随版本更新。

不单独展示 Z.ai 国际版。需要国际端点的资深用户继续使用“自定义兼容服务”；Lantern 不跨地域自动切换端点，也不假设国内和国际凭据可以互用。英文界面也不引入 Z.ai 这个名字。

### 1.1 用户群假设

首版用户群假设为中国大陆用户。英文界面服务的是想要沉浸式英文环境的中文用户，不代表海外发行，因此：

- 默认突出显示 DeepSeek 预设，不随界面语言变化。
- 不需要为“注册 DeepSeek 需要中国大陆手机号”准备海外替代路径。
- “获取 API Key”打开的是中文官网，界面不额外提示“此站点为中文”，那会破坏英文沉浸感。
- 界面自身的文案、状态词和步骤图标题仍须完整提供中英文两版。

## 2. 产品模型

### 2.1 术语

| 用户界面 | 内部含义 |
| --- | --- |
| 模型 | 一组可调用配置：服务商、地域端点、模型 ID 和凭据 |
| 模型目录 | Lantern 提供的可添加预设，不参与调用 |
| 调用路由 | 用户已经添加并启用的模型列表，顺序就是故障切换顺序 |
| 连接 | 用户提供自己的 API Key，并通过一次真实连接测试 |

代码中的 `AiProfile` 对应调用路由里的一个“模型”。运行时先选中优先级最高的 Profile，在其中按 Credential 顺序尝试密钥；该 Profile 的凭据全部不可用后，再进入下一个 Profile。

### 2.2 设置页结构

设置页的主板块名称使用“模型配置”，结构如下：

```text
模型配置

调用顺序
1. DeepSeek · deepseek-v4-flash   可用       按量付费
2. OpenAI · gpt-4o-mini           需要连接   按量付费
3. Ollama · qwen3.5               可用       本地

＋ 添加模型
```

- `+ 添加模型` 打开模型目录；用户选中预设后完成连接，再加入调用路由。
- 调用路由支持拖动排序，也保留键盘排序能力。
- 排在最上方的可用模型优先使用。
- 用户希望尽量少产生费用时，把付费模型拖到最后。
- 用户不接受任何费用时，不添加或禁用所有付费模型。
- 免费、按量付费、本地模型必须有清晰且稳定的类型标记。
- 高级字段（Base URL、模型 ID、温度、推理强度）默认收起；普通用户连接智谱时不需要编辑这些字段。

### 2.3 付费模型授权边界

用户主动添加、配置并启用一个标记为“按量付费”的模型，就表示允许 Lantern 在前序模型不可用时自动调用它。自动切换时不再逐次弹窗确认，否则故障切换失去意义。

Lantern 必须做到：

- 添加之前明确显示“按量付费”。
- 允许随时禁用、删除或调整到路由末尾。
- 不把应用升级中新出现的付费预设自动加入用户路由。
- 不把用户仅在目录里浏览过的模型视为已授权。
- 从免费模型降级到付费模型时，给一次非阻断提示（见 §5.4）。

不再单独提供“只用免费模型”开关。每个模型本来就有启用/禁用能力，禁用等同于“留在列表里但不参与路由”，再加一个总开关只是同一语义的第二个入口。

### 2.4 回答不做模型标注

不在每条回答旁边标注“由哪个模型生成”。阅读体验优先，正文区域不增加常驻元信息。用户想知道当前用的是谁，去设置页的调用顺序里看状态即可。

唯一的例外是 §5.4 的降级提示，因为它涉及花钱。

## 3. 智谱连接流程

网页登录本身不会把调用权限授予 Lantern。智谱官方当前文档要求用户登录后创建 API Key，并在请求中发送 `Authorization: Bearer YOUR_API_KEY`；没有可直接替代 API Key 的 Lantern 第三方登录流程。

正确流程：

1. 用户选择“智谱 GLM-4.7-Flash”。
2. 未配置时显示“需要连接”，不显示“暂时不可用”。
3. 点击“获取免费 API Key”，用系统浏览器打开官方 API Key 页面。
4. 页面内可用简短图示说明：注册/登录、创建 Key、复制 Key、返回 Lantern。
5. 用户回到 Lantern，将 Key 粘贴到输入框并点击“连接”。
6. Lantern 保存 Key 后发起真实连接测试。
7. 测试成功，状态变为“可用”，并将该模型加入调用路由。
8. 测试失败，保留输入上下文和可操作错误，不创建一个看似可用的路由项。

连接面板提供一张本地随应用发布的步骤图，依次表现“登录/注册 → 创建 API Key → 复制 → 返回 Lantern 粘贴”。图片不能包含真实 Key，也不要直接使用容易随官网改版失效的整页截图；按钮文字和输入框位置仍以当前官方页面为准。中英文可以共用无正文的示意图，步骤标题和辅助说明由界面 i18n 提供。图片加载失败时，完整流程仍能通过界面文字和官方链接完成。

建议状态词。每个词都必须对应一个确定的数据库状态，不能由界面自行归并：

| 状态词 | 数据库 `state` | 含义 | 典型恢复时间 |
| --- | --- | --- | --- |
| 需要连接 | 无（该 Profile 没有任何凭据） | 尚无可用凭据 | 用户操作后 |
| 正在验证 | 无（界面瞬时态） | 正在执行连接测试 | 秒级 |
| 可用 | `active` | 最近一次测试或调用成功 | — |
| 额度已用完 | `quota` | 免费额度或账户余额耗尽 | 1 小时 |
| 暂时不可用 | `cooldown` | 限流、超时、网络或服务端错误 | 限流按 `Retry-After`，缺省 60 秒；网络和 5xx 为 30 秒 |
| 需要重新连接 | `invalid` | Key 缺失、失效或被服务商拒绝 | 用户操作后 |
| 配置不可用 | `unavailable` | Profile 缺少必要配置，无法发起请求 | 用户操作后 |

“额度已用完”必须和“暂时不可用”分开。免费模型跑到额度耗尽是常态，它的冷却是 1 小时，而网络抖动只有 30 秒；两者共用一个词会让用户完全无法判断该等一会儿还是该换一个模型。恢复时间应当在界面上以倒计时呈现，而不是只给一个静态词。

首版不需要在 Lantern 内嵌网页，也不需要监听用户是否完成官网登录。浏览器只负责服务商账号和 Key 创建，Lantern 只接收用户主动粘贴的 Key。

## 4. 默认与升级行为

- 新安装且没有任何 AI Profile 时，在目录中默认突出显示智谱预设，不随界面语言变化（见 §1.1）。
- **不预置任何 Profile。** 空状态就是目录页本身，不写入一个“需要连接”的路由项。原因见下。
- 如果用户已经有 Profile，不改变其顺序、不替换端点、不自动插入智谱。
- 普通 AI 功能默认跟随调用路由，包括聊天、查词、翻译、解读和后台 AI 任务。首版不存在“某个功能固定用某个 Profile”的绑定；`AiRequestPurpose` 只区分 `Chat` 和 `Utility`，且只用于选择推理强度，不用于选择 Profile。若将来要做功能级绑定，那是独立特性，不在本文范围。
- 模型目录更新只能更新“可添加的预设”，不能改写已经安装到用户路由里的 Profile、端点、模型 ID 或凭据。

不预置 Profile 的理由是代码语义：`profiles(db, true)` 只按 `enabled` 过滤，播种出来的空 Profile 会被 `active_profile()` 选中，从而让嵌入向量源、凭据列表等依赖“当前 Profile”的地方以为 AI 已经配置好。这正是 §3 和验收标准要避免的“看似可用”。空状态放在目录页里不需要改动任何路由代码，用户看到的仍然是“打开设置 → 智谱预设被突出显示”。

## 5. 路由与故障切换

### 5.1 顺序

运行时按以下顺序选择：

1. 按 Profile `priority ASC` 遍历启用且未冷却的模型。
2. 在当前 Profile 内按 Credential `priority ASC` 遍历启用且可用的 Key。
3. 当前 Key 不可用时先尝试同 Profile 的下一个 Key。
4. 当前 Profile 没有可用 Key 或调用失败时，继续下一个 Profile。
5. 任意一次调用成功后停止遍历。

界面拖动顺序必须直接写回 Profile priority，不能再维护一份与运行时脱节的“显示顺序”。

### 5.2 应自动继续下一项的情况

- 免费额度耗尽或服务端限流（通常为 `429`）。
- 网络错误、连接超时、读取超时。
- 服务商 `5xx`。
- 当前 Profile 的 Key 缺失、失效或被拒绝；标记该项“需要重新连接”后继续。
- 当前模型或端点配置不可用，但请求尚未产生用户可见正文。

用户主动取消不触发故障切换。

### 5.3 首 token 边界

自动切换只允许发生在**尚未向用户输出有意义正文**之前。一旦已经输出正文，再换模型会造成重复、断句或两种回答混合，因此此时应保留已有内容并显示中断/重试状态。

空 SSE delta、仅协议元数据或空 reasoning delta 不算已经输出正文，不能因为这些事件阻断切换。

**非空 reasoning delta 算已经输出正文，之后不再切换模型。** 这是现有实现的行为（`openai_compat.rs` 中非空 reasoning 会置 `emitted`），本文确认保留：用户已经在界面上看到了思考内容，此时换模型会让界面出现两段互不相干的思考。代价是“模型思考了几秒才返回 429”这种情况不会自动降级，只会显示中断和重试；这是可以接受的取舍，实现和 review 不要再来回改。

### 5.4 跨请求的冷却与降级提示

故障切换不只影响当前这一次请求。失败会被写进数据库：Profile 和 Credential 都有 `state` 与 `cooldown_until`，冷却中的 Profile 在下一次选择时被整个跳过。也就是说免费模型限流一次之后，**接下来整个冷却窗口内的每一次新请求都会直接走到付费模型**，而设置页上免费模型仍然排在第一位。

这个行为本身是对的，不要改成每次请求都重试已知失败的模型。但用户是在无感状态下花的这笔钱，所以必须补上可见性：

- 一次冷却窗口内，第一次发生**免费 → 付费**的降级时，给一个非阻断提示。付费之间、免费之间的互相切换不提示；用户只需要知道“开始花钱了”这一个事实。
- 提示内容包含四项信息：从谁切走、切到谁、要花钱、多久恢复。例如：
  > 智谱 GLM-4.7-Flash 触发限流，已改用 DeepSeek（按量付费），约 1 小时后恢复
- 服务商没有给出恢复时间时省略最后半句，不要编造。
- 提示出现在发起请求的位置（划词就在阅读页，聊天就在聊天面板），不遮挡正文，自动消失，不打断流式输出。
- 同一个冷却窗口只提示一次；冷却到期后重新触发算新窗口，可以再次提示。
- “多久恢复”是这条提示的核心价值，它等价于告诉用户“你接下来这段时间都在花钱”。
- 用户手动点“重试”时忽略冷却，直接再试排在最前面的模型。用户主动的动作应当盖过自动记录的健康状态。

## 6. 内置目录与更新

### 6.1 首版目录

首版至少包含，顺序即目录顺序：

- DeepSeek：默认推荐，排在第一位。端点 `https://api.deepseek.com`（不含版本段，由公共端点函数补 `/v1`），默认模型 `deepseek-v4-flash`——官方已不再提供 `deepseek-chat`，实现时按官方文档核对过。想要更强能力的用户可在高级设置里改成 `deepseek-v4-pro`，字段一律保持可编辑。
- OpenAI、Anthropic、Ollama、自定义兼容服务：保留现有能力。自定义排在最后，它是逃生口而不是推荐项。
- 目录列表下方固定一句提示：讲解和语法分析依赖模型的理解能力，参数量很小的模型（包括大多数本地模型）会给出看似合理、实际错误的解释，建议选主流中大型模型。提示放在挑选模型的那一刻，不做成弹窗，也不在每次添加时拦截。

**首版经实测决定不内置任何免费模型。** 原因不是找不到免费接口，而是能免费拿到的小参数模型输出质量不达标：它们在语法拆解和词义辨析上会自信地说错话，而这正是本产品最核心的用途。免费模型的准入条件保留在下面，将来若有免费模型在**质量**上过关仍可加入——门槛是质量，不是价格。

其他免费模型只有在以下信息均能从服务商官方资料确认后才能加入：

- 稳定的官方 API，而不是网页逆向接口或共享代理。
- 明确允许第三方客户端调用。
- 用户能够自行注册并获得凭据。
- 免费范围、速率限制和地域限制能够准确描述。
- 有可维护的服务商官网、文档、Key 页面和隐私政策链接。
- **输出质量经真实 Key 实测达标**：至少在语法拆解和词义辨析上不出现自信的错误。这一条是 2026-08-02 补上的，也是撤掉智谱预设的直接原因。

### 6.2 后续更新机制

不要直接拉取并执行第三方 GitHub 仓库配置。第三方列表可以作为人工发现来源，但不能成为 Lantern 的信任根。

如后续需要在线更新，采用 Lantern 自己维护的版本化、签名模型目录：

- 自动检查目录新版本；用户也可手动刷新。
- 下载内容只包含预设元数据、费用类型、官方链接和展示文案。
- 客户端校验签名、schema 版本和字段白名单。
- 更新不包含 API Key，不执行脚本，不覆盖用户路由。
- 已添加 Profile 的端点变化必须由用户明确确认，防止把 Key 和书籍文本发送到被篡改的主机。
- 远程目录不可用时继续使用随应用发布的内置目录。

该在线目录不属于首版阻塞项；首版随应用版本更新内置预设即可。

## 8. 必须先修的技术问题

### 8.1 `/v4` URL 拼接

当前 OpenAI-compatible 适配器只识别以 `/v1` 结尾的 Base URL。智谱 Base URL 为：

```text
https://open.bigmodel.cn/api/paas/v4
```

现有逻辑会错误拼成：

```text
https://open.bigmodel.cn/api/paas/v4/v1/chat/completions
```

正确地址是：

```text
https://open.bigmodel.cn/api/paas/v4/chat/completions
```

同一套拼接规则目前在四处各写了一份，全部有同样的缺陷：

| 位置 | 用途 |
| --- | --- |
| `src-tauri/src/ai/openai_compat.rs` | 聊天 |
| `src-tauri/src/ai/router.rs::models_endpoint` | 模型列表端点推导 |
| `src-tauri/src/ai/router.rs`（拉取模型列表处） | 模型列表请求 |
| `src-tauri/src/ai/router.rs`（embeddings 处） | 向量嵌入，语义检索使用 |

**embeddings 这一处容易被漏掉**，但智谱的 `/v4/embeddings` 会被同样拼成 `/v4/v1/embeddings`。

实现要求：抽出一个公共函数（例如 `compat_endpoint(base, path)`），四处全部改为调用它，规则从“结尾是 `/v1` 就不补”放宽为**“路径末段已经是 `/v{数字}` 就不再补 `/v1`”**。这样 `/v4`、将来的 `/v5`、其他网关的 `/v3` 一次性都正确，而不是为智谱加一个特判。

测试至少覆盖：

| Base URL | Chat 结果 |
| --- | --- |
| `https://api.openai.com` | `https://api.openai.com/v1/chat/completions` |
| `https://host.example/v1` | `https://host.example/v1/chat/completions` |
| `https://open.bigmodel.cn/api/paas/v4` | `https://open.bigmodel.cn/api/paas/v4/chat/completions` |
| `https://gateway.example/v3` | `https://gateway.example/v3/chat/completions` |
| 带尾部 `/` 的上述地址 | 与无尾部 `/` 相同 |

并对 embeddings 路径重复一组同样的用例。不要只在智谱字符串上做散落的特判；聊天调用、连接测试、模型列表和 embeddings 必须复用同一套端点规则。

### 8.2 Provider 预设

推荐增加用户可识别的 `zhipu` Provider，内部仍复用 OpenAI-compatible chat adapter：

- 前端 Provider 校验允许 `zhipu`。
- `AiServiceCard` 增加智谱默认值。
- Rust Profile 归一化和 Provider 分派允许 `zhipu`。
- 默认模型固定为 `glm-4.7-flash`，普通模式不要求拉取模型列表。
- 连接测试必须使用所保存的同一 Base URL、模型和 Key。

如果为了最小改动暂时在数据库中保存为 `custom`，也必须另外保存稳定的 preset ID；不能仅靠 label 文本识别智谱，否则用户改名后升级和展示都会失去身份。

### 8.3 错误分类

**现状已经正确，这里要做的是补回归测试，不是修 bug。** `AiErrorKind::retryable()` 已经把 `CredentialInvalid` 和 `Auth` 算作可继续，遍历会先换同 Profile 的下一个凭据，凭据用尽后继续下一个 Profile。语义是：认证失败对当前凭据不可重试，但对整个调用路由仍然可恢复。实现时不要“修正”这段本来正确的逻辑，而是加测试锁住它。

需要测试覆盖的行为：

- 某个 Profile 的认证失败或 Key 失效不会终止遍历，后续 Profile 仍会被尝试。
- `429` 能进入冷却并继续下一项。
- `Retry-After` 可用时优先采用服务端时间。
- 额度耗尽落到 `quota` 状态而不是普通冷却，冷却时长与状态词按 §3 的表。
- 用户取消不会污染 Profile/Credential 健康状态。
- 已输出正文（含非空 reasoning）后不再切换。

## 9. 安全与隐私

- 不在安装包、前端源码、远程目录或日志中放置 Lantern 共享 Key。
- 用户 Key 继续保存在本地 `secrets.db`，不进入 iCloud 同步和设置导出。
- 设置 API 不回显已保存的完整 Key；界面只显示掩码后缀。
- 打开服务商网页必须使用固定 HTTPS 官方链接。
- 模型卡要让用户知道选中文本、问题和必要上下文会发送给该服务商，并受其隐私政策约束。
- 自动切换到下一模型时沿用同一请求上下文；这意味着加入路由的每个服务商都可能收到内容，隐私说明必须覆盖这一点。
