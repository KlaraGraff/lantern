## 视觉与交互复核

Lantern 的基调是安静、克制、书卷感、内容优先的桌面阅读器：中性和纸张色为主，紫色只作少量强调；正文和阅读事实优先，工具 UI 退居其次；用留白、细边框和轻层次组织信息，避免营销感、卡片堆叠、大面积紫色、嵌套卡片和层层弹窗。

请在不抢占用户前台的前提下使用后台或 Headless 测试。对真实 Reader 集成无法用静态 HTML 证明的部分，使用可行的后台 Tauri/Electron/Playwright 方式；如果环境确实不能验证，明确写成边界，不得假称通过。

至少检查：

- 1440px 左右桌面宽度和一个窄窗口状态；
- 浅色/纸张主题，能安全覆盖时再检查深色主题；
- 正常、加载、空态、失败、重试、确认和不可用状态；
- 中文和英文；
- 内容是否被面板、播放器、浮层或固定栏遮挡；
- 文字、按钮、计数和长书名是否溢出；
- 固定顶部/底部与内部滚动是否发生重叠；
- 键盘焦点、Escape、返回、tooltip、ARIA 和减少动态效果；
- 正式页面是否意外带入样板的演示控件或说明文字。

逐项对照 P2.1–P3.4：

- P2.1：无边框下载图标、统一导出弹窗、Markdown/CSV/Anki、预览和保存状态。
- P2.2：原句挖空；提示顺序“读音 → 已保存中文句意 → 答案”；不显示首字母、字母数或拼写长度。
- P2.3：可重排内容的两端对齐、语言断词、四档段距、智能首行缩进；默认保留出版社样式。
- P2.4：清晰的“本书单独设置 · 跟随全局”；同一右侧面板内换页；搜索/当前结果全选固定顶部、确认固定底部、列表内部滚动。
- P2.5：顶部参与布局的连续朗读播放器和可恢复的朗读胶囊；不审查尚未拍板的旧朗读标记统一。
- P3.1：阅读历程/阅读日历同页切换，默认历程，切换器最右；统计可复算；AI 只叙述本地事实；增强字体状态完整。
- P3.2：页边笔记轨与正文引用对齐，正文参与布局，窄窗退化合理，失败保留草稿。
- P3.3：词上小字/页边释义可选；主设置和 Reader 快捷入口控制同一个全局状态；窄窗退化；不产生每书覆盖。
- P3.4：正文就地轻量人物/术语卡；默认防剧透到当前位置；整书范围明确确认；跳转成功才关闭；窄窗不遮正文。

每个视觉问题必须附：实际截图、对应正式样板、预期与实际差异、影响、复现窗口尺寸和建议修正方向。不要只写“感觉不一致”。

## 功能与代码审查

从入口一直追到状态、持久化、同步、错误处理和测试，不要只审组件表面。重点检查：

1. `Reader.tsx` 及 hooks 的 effect/callback 依赖是否会触发 Reader 重建、重复监听、重复请求或重复计时。
2. 开书、关书、切书和卸载时的异步任务是否可能晚到并写入旧 Reader/旧书状态。
3. Foliate document 生命周期、章节切换和 DOM 注入是否幂等；是否可能访问已销毁 document、重复包装正文、破坏 CFI、选区、高亮或保存位置。
4. P2.4 防抖写入、恢复全局、提升全局和批量清理是否存在竞态；Rust 事务、同步 outbox 与 tombstone 是否保持一致。
5. P2.5 连续朗读跨页/跨章、语言切换、暂停/停止、自动翻页和资源清理是否可靠，且不污染跳转历史。
6. P3.1 计时在闲置、失焦、睡眠/唤醒、切书、退出和崩溃恢复时是否重复或丢失；30 秒/5 分钟规则是否端到端一致。
7. P3.1/P3.4 AI 请求、日志、缓存键和错误诊断是否严格限制在允许字段，是否可能泄漏正文、笔记、高亮或未读内容。
8. 增强字体下载是否有可信 manifest、大小上限、进度、SHA-256、临时文件清理和原子替换。
9. P3.2/P3.4/AI/书签/生词工作区是否互斥；跳转失败、返回、关闭和窄窗布局是否恢复正确。
10. 导出 CSV/Markdown/Anki 的转义、超大数据、取消保存、失败重试和敏感内容日志是否安全。
11. 中英文 key 是否同步，是否存在硬编码文案、焦点不可达、ARIA 错误、按钮热区过小或窄窗溢出。
12. 是否存在真实重复或过长组件可通过现有模式简化；不要为追求抽象而引入新依赖或大规模重构。

请搜索全部调用者后再下结论。发现 bug 时给出根因链路，不要只描述症状。

## 报告格式

请把完整报告写入 `docs/impls/reader-p2-p3-independent-review-YYYY-MM-DD.md`，聊天中只给简短结论和文件链接。

报告按以下顺序：

1. **结论**：通过 / 有条件通过 / 不通过，并说明最主要理由。
2. **问题清单**：按 Critical、High、Medium、Low 排序。每项必须有文件与行号、触发条件、用户后果、根因、证据、建议修正和缺失测试。
3. **视觉一致性矩阵**：P2.1–P3.4 逐项标记一致、轻微偏差、明显偏差或未验证，并链接实际截图。
4. **功能与跨功能矩阵**：入口、状态、持久化、同步、错误恢复、响应式和能力边界。
5. **代码优化建议**：只列有明确收益和边界的建议，区分“bug 必修”和“可维护性优化”。
6. **验证结果**：逐条命令与结果，不只写“测试通过”。
7. **真实外部边界**：未能验证的 Tauri、设备、iCloud、AI、字体下载或特定书籍场景。

如果没有发现问题，明确写“未发现可复现问题”，同时说明仍存在的测试盲区和环境边界。不要为了显得有产出而制造问题。

本轮不要扩展 P3.5 双语整书翻译，不要统一旧句子/段落朗读标记，不要把 P3.4 回退面板改成正式方案，也不要改变产品样式基调。
