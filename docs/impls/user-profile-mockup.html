附录乙 · 自学习机制（预留设计——现在建钩子，算法后做）

目标：系统改动画像之后，要能知道这次改动是把效果推向了预期方向，还是被用户顶了回来；并让这些信号反过来喂总结器。

  1. 版本留痕。每次总结落一条版本记录（profile_revisions：前后卡片全文、触发原因、时间）。没有留痕，后面一切效果归因都无从谈起——这是第一块钩子，实现第一版时就建表。
  2. 修正信号记账。用户对某维度的删除 / 移动 / 改写记为修正事件（profile_events，type = correction，带维度键和用户改后的说法）。注意：台账本身永不直接喂给总结器——堆积的「上次别这样写」负例会互相打架、越攒越糊（调研笔记第四节）。它经附录甲「修正信号三层」压成每维度一行的裁决状态后才进提示词——对应你说的第 1 条：把已经总结的内容改对，但改的依据永远是「该维度最新的那次裁决」，不是全部历史。
  3. 效果信号记账。画像改动后，观察追问走向：同维度问题是否复发、用户是否在对话里反向纠正 AI（「不是让你这样」类表述）。记为 effect 事件——对应你说的第 2 条：针对效果不好的情况进一步优化。第一版只记账不判断，判断规则等数据攒出来再定。
  4. 事件满额自动触发。correction + effect 事件攒满一批（阈值同攒批节奏），即使新追问没到 20 条也触发一次针对性再总结——记录满了不能干等。
  5. 可选上传（远期）。用户体量足够后，提供自愿上传：匿名化的「画像改动 → 效果走向」统计（不含原文、不含画像内容本身），用于优化全局的总结器提示词与机制。默认关闭、明确一次性授权、可随时反悔——隐私纪律与现有自动分析条目一致。
