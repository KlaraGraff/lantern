# 出题后台化 · 返回与完成提醒

> 样张：`quiz-generation-background-mockup.html`（状态 A–C），已拍板。
> 架构前提：出题会话（`src/pages/quiz/generation-session.ts`）是模块级单例，本来就跨路由存活——出题中屏只是「望进去的窗户」。本次只补三个 UI 口子，不动会话架构。

## A · 出题中屏加「返回」

`GeneratingScreen.tsx` 顶栏左侧加「← 返回」（`navigate(-1)` 语义：回到来路继续看书/干别的）；右侧「取消」语义不变（放弃本次出题）。底部说明改为去向告知：「可以返回去看书，出好后顶部会提醒你」。

## B · 全应用顶部完成横幅

新组件 `src/components/QuizReadyBanner.tsx`，挂在 App 壳层（所有路由之上）：

- 订阅出题会话（`useSyncExternalStore`，同 GeneratingScreen 现有接法）。
- 触发时机：**首篇就绪**（会话状态里 `paperId` 从无到有）——这一刻确实能开始做题，其余篇按渐进发卷既有设计在做题时后台补齐。
- 内容照样张 B：「✓ 今日词卷已出好，可以开始做题」+「去做题」（跳 `/quiz/paper/{paperId}`）+「×」。约 10 秒不理会自动收起。
- **抑制规则**：当前路由已在该卷（`/quiz/paper/{paperId}`）时不弹——人就在现场，不用提醒。
- 文案不带催促/倒计时（既有红线）；键放 `quiz.readyBanner.*`，双语言。

## C · 词卷出卷页停靠状态卡

`SetupTab.tsx` 现有「未做完的卷」横幅扩展成样张 C 的两种态：

- **已出好**：标题「今日词卷已出好」，副行「{日期} · {难度} · {n} 题就绪」，按钮「开始做题」。
- **出题中**：标题带「出题中」紫标签，副行显示当前进度（如「第 1 篇撰写中」，从会话状态取），按钮「看进度」→ 回出题中屏。
- 出题**失败**时同一张卡承接：按钮仍是「看进度」，进去是既有的错误+重试界面——错误不需要新表面，卡片保证它不静默丢失。

## 验收

- `npm run test:unit`、`tsc`、`eslint` 全绿；会话层如有纯逻辑改动补单测。
- 人工验收路径：发起出题 → 返回读书 → 首篇就绪时横幅出现 → 点「去做题」落到卷子；另一轮不点横幅，回词卷页看停靠卡两种态。
