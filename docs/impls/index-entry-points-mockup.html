名字为什么这么改。
  • 增量更新 → 补齐索引（没建过时显示「建立索引」）。它本来就是「缺什么补什么」的那个按钮，四个阶段全包。叫「增量」把它说小了，你就是因此没点它。
  • 全量重建 → 重新切分块，并且收进「高级」。它实际只重切分块，向量和摘要一个都不碰——叫「全量重建」是三个字里错了三个字。
  • 重新生成摘要 → 重写摘要，也收进「高级」。
  • 嵌入覆盖 → 向量覆盖。「嵌入」是行话，界面上其它地方也都说「向量」。
第五步：人物别名。
  • 它单独占一步，不并进「章节摘要」。这一步也是一趟模型调用，耗时和摘要一个量级——藏在别人名下，进度条会在最后停住不动，而「停住不动」正是这一轮要治的病。
  • 上面那四张统计卡不加第五张。别名在弹窗里本来就有自己的一整块（人物、别名条数、你教过的哪几条都在那儿），再挤一张卡进去只会把「状态 / 分块 / 向量覆盖 / 向量模型」这排挤散。
  • 第 2 屏那句话只报最要紧的那个缺口，缺向量就说缺向量，不把五个阶段的缺失情况列成清单。那句话的作用是让人知道下一步按哪个按钮——按钮只有一个，所以话也只需要一句。
这次故意没做的。
  • 不做自动建索引。导入一本书就自动跑向量，等于在你不知情的时候替你决定动用哪个模型、动用多久。要不要跑，你按按钮。
  • 批量不并发。逐本串行。并发只会让几本书互相抢同一个模型，总时间不会变短；而且串行才好停、好续。
  • 不加全局进度浮窗。先看这两本实际跑多久。如果一本几十秒，那关掉设置就跑完了，浮窗是多余的 UI。
