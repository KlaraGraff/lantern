人物别名与分级路由

解决一件具体的事：问「达西第一次向伊丽莎白求婚」，而书里写的是 Darcy 和 Elizabeth。关键词检索按 token 对，两边一个词都对不上。

做法分两层。第一层是一张按书存的别名表，导入时建一次，查询时零模型调用。第二层是把查表的结果如实告诉用户——命中得干净就别废话，命中得含糊才解释。

Elizabeth Bennet 伊丽莎白✕ 丽萃✕ Lizzy✕ ＋ 自动

为什么不给描述另开一个区块。这张表已经按人分组了，而一条描述说的就是某个人——「那个总在拍马屁的牧师」属于 Mr. Collins 那一行，不属于别的地方。拆开等于让用户为了搞清楚「柯林斯一共有几种叫法」看两个列表。
为什么要单独标 ≈。人名按字面对，描述按意思对。混成一样的 chip，用户会以为行为相同，然后不理解为什么换个说法有时管用有时不管用。这个差别不说清楚，功能就是玄学。
为什么把当时的原问句挂在下面。「那个总在拍马屁的牧师」单看，六周后你想不起来自己为什么教过它、当时想找什么。配上原问句它就自解释了——而这正是决定「要不要删掉」时唯一需要的信息。
只给删，不给改。改文字要重算向量、改两张表，而教的入口就在对话里，删掉重教一遍更快也更清楚。

⚠ 带 ≈ 的两条现在不生效。它们靠意思匹配，需要「搜索模型」；那个开关现在是关的。人名不受影响，照常工作。

这一条不能省。描述类跟向量检索共用同一个开关——用户在设置里关掉向量检索，或者搜索模型连不上，这些别名就悄悄不工作了，而表里还好端端列着。列着但不生效，是比不列更糟的状态：用户会以为教过了，然后把答不上来归咎于 AI 笨。
变灰而不是隐藏，因为它们没有丢，开关打开就回来。

第二部分 · 分级披露

置信度不问模型，从查表结果数出来：唯一命中 = 高，命中多个 = 中，一条没中 = 低。模型自报的「我很确定」在它错的时候也会说确定，数出来的不会。

5高 · 唯一命中 界面上什么都不多说，直接答
柯林斯是怎么向伊丽莎白求婚的？

他先郑重其事地列了三条理由——牧师该做榜样、这样能增添他的幸福、还有凯瑟琳夫人特意嘱咐过[S1]。伊丽莎白几次想打断都没成功，等他说完才明确回绝，而他把这个回绝当成了年轻姑娘照例的推辞[S2]。

「柯林斯」和「伊丽莎白」各自唯一命中，没有歧义，就不该在回答前面加一句「我把柯林斯理解为 Mr. Collins」。那句话在这里是噪声——用户本来就知道自己在说谁。

6中 · 命中多个 先说按谁理解的，一句话，可当场换
达西小姐弹琴那段是在哪里？
按 这本书里有两位达西小姐，我按 Georgiana Darcy 找的。换成 Elizabeth 眼中的 Miss Darcy

在彭伯利。伊丽莎白和嘉丁纳夫妇到访时，乔治安娜被哥哥请出来待客，弹琴那一段紧接在宾利小姐出言试探之后[S1]。

这一行的位置很关键：在回答上面，不在下面。放下面等于让用户读完一整段才发现找错了人。

7低 · 一条没中 明说没认出来，别装作认出来了
那个总在拍马屁的牧师后来怎么样了？
未认出 没认出 那个总在拍马屁的牧师 是谁，按字面在书里找的。

书里有一位牧师符合这个说法：Mr. Collins。他在结尾仍住在 Hunsford，靠凯瑟琳夫人的赏识过活[S1]。

低置信度不等于不回答。检索照跑，只是把「我是猜的」摆在前面。
按钮在回答下面，不在披露行旁边——「Mr. Collins」这个名字是回答里才出现的，在它出现之前问「对不对」，用户没有可对的东西。

8点完之后 原地换成回执，不新起一轮对话

…他在结尾仍住在 Hunsford，靠凯瑟琳夫人的赏识过活。

✓ 已记下：这本书里「那个总在拍马屁的牧师」指 Mr. Collins 撤销

按钮那一行原地变成这条回执，不新起一轮对话——用户点的是「确认」，不是「提问」，不该在聊天记录里多出一来一回。
写回只影响这本书，并且立刻出现在第一部分那张表里（带底色的那种 chip），随时能删。一条学错的别名比没有别名更糟——答案开始跑偏，而用户不知道为什么。所以它必须在表里看得见。

这次不做的

把模糊问句整个交给模型改写成检索词——那是每问一次就掏一次模型，包括本来就检索得很好的大多数问题，回答开始吐字前先卡一秒。真要解决「第一次捞得不好」，正确做法是让模型能主动再检索一次（换个词自己再捞），而不是加一个所有人都要交过路费的前置阶段。那是更大的改动，排在这个后面。
