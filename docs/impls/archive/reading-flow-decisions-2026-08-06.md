## 一、生词入口：观察区 + 第 3 次自动转正

### 1.1 现状（必须先说清）

**当前一次都不会自动收。** 代码里没有任何自动加入生词本的路径，
`add_vocab_word` 的六个调用点全部挂在按钮上。降级逻辑的注释是明写的：
在那里替读者建条目，等于把他从没选择保留的词塞进他的词表。

后果见动线图图 4：掌握度、正文三阶段标注、复习堆，三件事全部只对
`vocab_words` 里的行生效。没收藏的词，曝光照记，结算时找不到对应条目直接跳过。

### 1.2 定下来的方案

两层，一起做：

| 层 | 谁进来 | 进来之后 | 读者看得到吗 |
|---|---|---|---|
| **观察区** | 查过一次的词，自动 | 掌握度照常升降、正文标注照常走 | 默认**看不到**，在生词列表里被筛掉 |
| **生词本** | 同一个词查到**第 3 次**，自动转正；或读者手按「收藏」，随时 | 同上，外加出现在生词列表、参与复习堆 | 看得到 |

判定用 `lookup_records` 按 `(book_id, normalized_text)` 汇总的 `lookup_count`。
注意不能只看单行——那张表对 `(book_id, cfi, normalized_text)` 有唯一索引，
所以「同一位置查 3 次」和「三个不同位置各查 1 次」是两种写法、同一个现象，
必须求和。复习堆的堆 1 已经是这么算的，直接复用同一段判据。

### 1.3 三条实现约束

- **观察区不是一个新概念，是一个筛选器的默认值。** 不给它名字、不给它入口、
  不在侧栏加一行。读者眼里仍然只有「生词」一个地方，只是默认不显示还没查够
  3 次的词。第六套分类是本方案最大的风险，见第五节。
- **转正要留痕。** 走 `mastery_events` 记一条，理由写「你在《X》里查过它 3 次，
  已经替你记下了」。自动做的事必须能被读者看见并推翻——这是原设计 §2.6 的死规矩。
- **来源标记照旧分两种。** 自动转正的算「读出来的」，手按收藏的算「你标的」。
  将来发现自动这套不准，只回滚自动那部分。

### 1.4 为什么是 3 不是 2

第 1 次很多只是当时不确定，看一眼就过去了，不该进词表。
第 2 次仍可能是隔了很久的偶然重逢。
到第 3 次，这个词在这个人身上是稳定的障碍，替他收下的理由硬到能写在界面上。
代价是转正更慢；但观察区已经在底下跑掌握度了，慢的只是「出现在列表里」这件事，
不是「开始学」这件事。

## 二、读完判定：进度到头 ≠ 读完

### 2.1 问题

单看进度 100% 会被两种动作骗过去：一路狂翻到底、直接拖到最后一页看结局。
这两种都会把进度顶满，但书没读。

### 2.2 定下来的判据

**两个条件同时满足，才自动标记为已读完：**

1. 进度 ≥ 95%；
2. **覆盖率**：这本书里以正常速度停留过的屏数 ≥ 全书屏数的 80%。

95% 而不是更高，是因为尾巴的长度不是固定比例：版权页、致谢、索引、
作者其他作品广告，在一本长篇里占 1%，在一本两百页的小书里可能占 5%。
按比例卡上限，短书天然吃亏——它永远差最后那几屏，永远等不到自动标记。
把上限放宽，误标的风险由第 2 条覆盖率兜住，那一条不受书长影响。

「正常速度」直接复用现成的 `is_screen_too_fast`——比该读者自己的中位速度快
3 倍以上的屏不算数。基准是他自己，所以读得快的人不会被误伤。

拖到最后一页的情形自然被挡住：中间那些屏根本没有记录，覆盖率上不去。

### 2.3 不满足条件时做什么

**不自动标，也不弹窗。** 在最后一屏放一行小字，和章末那行同款克制：
「读到这儿了？标记为已读完」。看见了才按，翻过去就没了。

### 2.4 一个已知的失败方向，可以接受

每屏行为记录**只在本机、不同步**。一本书在 Mac 上读一半、在 iPhone 上读完，
两台设备各自的覆盖率都不够 80%，于是不会自动标记，退化成那行小字。

这是安全的失败方向：**宁可漏标，不可错标。** 错标一本没读的书，
会连带触发读完汇总、算进阅读统计，读者要手动改回去；漏标只是少了一次自动。

## 三、读完汇总：失败不再静默

### 3.1 现状

`run_book_finished_analysis` 现在是全静默的：闸门关着、没配 AI、额度用光、
断网、已经生成过——五种情况一律 `Ok(false)`，什么都不发生。

理由当时写得很清楚：读者按的是「标记已读完」，不是「给我总结一下」，
为一个他没提的请求报错，比没有总结更糟。

### 3.2 为什么要改

这个理由在别的自动任务上成立，在这一个上不成立。
**读完一本书的汇总是有成就感的时刻，它不是后台杂务。**
静默跳过的代价不是「少了个提示」，是读者根本不知道自己错过了什么——
他会以为这个功能不存在。

### 3.3 定下来的做法

区分两类失败，不要一刀切：

| 情况 | 怎么处理 |
|---|---|
| 闸门关着 | 维持静默。这是读者自己关的。 |
| 这本书已经生成过 | **不再是静默跳过，而是把那份汇总留在原地随时能看**，见 §3.4。 |
| 没配 AI / 额度用光 / 断网 / 模型报错 | **在书上留一个待生成的标记**，阅读统计页那本书的汇总位置显示占位卡，配一个「重新生成」。 |

关键是**留痕的位置**：不弹窗、不推送、不在图标上挂角标——那些是原设计
§十一明确不做的。占位卡是静态的，读者下次走到阅读统计页才看见，
但**一定看得见**，而不是消失。

现有的手动生成路径（`ReadingStats.tsx` 里已经有错误展示和重试）直接复用，
只需要把自动失败的状态记下来，让占位卡知道该出现。

### 3.4 生成过的汇总，留着，而且能重生成

原来的逻辑是「这本书有汇总了 → 什么都不做」，于是那份汇总只在生成的当下露过一面。
这不对：**读完一本书的汇总是读者会想回头看的东西**，不是一次性通知。

定下来两条：

- **生成过的汇总常驻**。在那本书自己的位置（书籍详情 / 阅读统计里这本书的卡片）
  一直挂着，随时点开。
- **旁边永远有一个「重新生成」**。读者把一本书重读一遍，是又付出了一次，
  理应能拿到一份反映这次阅读的新汇总——而不是被系统告诉「你已经读过了」。

自动触发仍然只跑一次（避免反复标记书架时重复计费），
但**重新生成是手动的，不设次数限制**。旧的那份被覆盖，不做版本历史——
读者要的是「这次读完的收获」，不是一份汇总的编年史。

## 四、补齐设计里已拍板、代码里还没有的四项

按「错了会怎样」排优先级（原设计 §6 的分类法）。

### 4.1 本地校准表（最该先做）

现在只做了一半：阅读速度中位数在用，**查词率还没有**。
后果是对每千词查 15 个的人和查 1 个的人，「没查」这个信号被当成一样重——
而设计 §5.2 说这两个人的含金量差十倍。

要的东西很小：一张本地表，几个统计量 + 各自的样本量 + 上次更新时间。
每天启动重算一次。两条护栏照原设计：样本不够用默认值；
**重算不追溯改写已有的学习状态**。

不同步，本机产物。

### 4.2 反哺英语水平的提醒

判定逻辑已经写好（`src/pages/reading-stats/level-observation.ts`，未提交），
还没接进阅读统计页。要接的是：一次温和的、可拒绝的提醒，时机在读完一本书之后。
三条护栏照原设计 §7——证据不够强不提、拒绝一次闭嘴三个月、
说「调了会发生什么」不说「你的水平不够」。

### 4.3 书籍详情页与难度对比

页面已写（`src/pages/BookDetails.tsx`、`src/pages/book-details/`，未提交），
难度数据已经在算（导入/转码完成后 `schedule_book_difficulty`）。
缺的是「这本书的用词比你平常读的难不少」这个对比提示和它的两个出口。

### 4.4 追问困难分类

一行都还没有。做法照原设计 §5.5：**事后批量，不实时**——
攒够 20～30 条追问，用一次便宜模型统一分类（词义 / 句法 / 指代 / 文化背景）。
不碰实时对话、不增加延迟。做的时候要在「自动分析」清单里登记一行。

## 五、单词的分类，对读者是不是负担

当前并存的分类维度，一共五套：

| # | 维度 | 读者看得到吗 |
|---|---|---|
| 1 | 掌握度四档：新 / 学习中 / 熟悉 / 已掌握 | 词详情页看得到 |
| 2 | 来源两种：读出来的 / 你标的 | 词详情页带标记 |
| 3 | 正文三阶段：释义 / 虚线 / 无 | 读书时一直在看 |
| 4 | 复习四堆 | 进复习板块看得到 |
| 5 | 观察区 / 生词本（本轮新增） | **不应该看得到** |

### 5.1 对不管这些的读者：零负担

这是设计成立的地方。四档和三阶段他都不需要理解——
他只会注意到**正文里的标注越来越少**，那就是进度条。
原设计 §3 的原话：释义的存在本身就是进度条，
这比「已掌握 137 词」有力得多，因为它出现在他真正在看的地方。

复习堆同理：堆名就是一句大白话，不需要先学会什么叫堆。

### 5.2 负担一：同一个词，两个地方两种说法

拿一个具体的词走一遍。你在《傲慢与偏见》里查了 `countenance`（神色）。

往后它会在三个地方出现，各说各的：

| 你在哪看到它 | 它长什么样 / 被称作什么 |
|---|---|
| 正文里，刚查完那几天 | 旁边挂着中文「神色」 |
| 正文里，读熟一点之后 | 释义没了，只剩一条虚线 |
| 生词页里 | 一个标签，写着「熟悉」 |
| 复习页里 | 在「你在《傲慢与偏见》里查了 3 次的词」那一堆 |

问题就在第二行和第三行之间：正文里是**一条虚线**，生词页里叫**「熟悉」**。
这是同一件事的两种说法，而两者之间的换算读者看不见。于是他会问：

> 它说我「熟悉」了，那正文里那条虚线又是什么意思？我到底会了没有？

**解法不是去解释这套映射关系，是直接给他看。**
在生词页那个词的详情里，画一小段示例正文，标上「现在它在正文里长这样」，
底下那条虚线原样画出来。读者一眼就把两边对上了，不需要学任何规则。

### 5.3 负担二：观察区，如果我们不小心给它做了张脸

再走一个例子。你查了 `serendipity`，就查了这一次。

按新方案，它已经进观察区了，后台在替它算掌握度。但生词页里找不到它。

**如果我们给观察区起个名字、在侧栏加一行「观察中 (23)」**——
读者一定会点进去，然后开始想：

> 这 23 个词算不算我的生词？我要不要管它们？为什么它们不在生词里？
> 是不是我漏做了什么？

这就是凭空给他多加的一件操心事，而他什么也没多得到。

**正确做法是什么都不加。** 生词页就是生词页。
`serendipity` 被查够 3 次的那天，它自己会出现在里面，
并且带着一句「你查过它 3 次，已经替你记下了」。
前面那两次背后发生了什么，读者**根本不需要知道**。

这就是 §1.3 那条约束的全部意思：观察区是个内部机制，不是一个要教给读者的概念。

### 5.4 一条收口的规矩

对外只讲两件事：**这个词现在什么状态**（四档，大白话），
**为什么是这个状态**（一句话，从时间线里取）。
不要再引入第六套分类。

## 六、复习堆的 AI 整理：做，但默认关闭

**拍板（用户，2026-08-06）：实现它，但在「自动分析」清单里默认关。**
先本地自用，内测分发时看真实反馈，再决定要不要长期开着。

这是本项目里第一个**默认关**的自动分析项，理由与原则（§12.1「默认关的功能等于没做」）
不冲突：那条原则针对的是**已经确信有价值**的功能——默认关会让读者永远发现不了它。
这一项恰恰相反，它的价值本身就是待验证的，默认开等于拿读者的额度替我们做实验。

实现时的三条约束：

- 在「自动分析」清单里正常登记一行，写清什么时候跑、发什么、上月花了多少。
  **不能因为默认关就不登记**——那样读者打开它的时候等于开一个盲盒。
- 规则堆**不被替换**。AI 整理是叠加在规则堆之上的一层，关掉之后
  复习板块必须和现在完全一样，一个堆都不少。
- 内测时要能分辨：读者是「用了觉得好」还是「压根没打开过」。
  没有这个区分，反馈就没法读。

下面四条是当初主张砍掉的理由，保留下来作为内测时的验收提问——
如果实测下来这四条都没发生，那它就该转成默认开：

1. **堆的全部说服力，来自「它说的是我干过的事」。**
   现在四个堆的理由是从数据库里数出来的事实——「你在这本书里查过它 4 次」，
   可验证、可回溯、永远不会说错。AI 生成的分组理由说错一次，
   读者对整个板块的信任就没了，而这个板块除了信任没有别的资产。
2. **它是所有自动 AI 调用里最贵的一个。** 每天一次、跨全部生词，
   而产出只是「换一种分组方式」——不是读者拿不到的信息。
3. **规则堆是确定的。** 同样的数据每次算出同样的堆。
   AI 分组今天一个样明天一个样，读者会以为自己的数据变了。
4. **原设计自己定过这条原则：能本地算的绝不花钱问 AI**（§5.5 的框注）。
   分组本地算得出来，「他卡在词义还是句法」本地算不出来——
   同样一次调用，该花在后者身上。

## 七、讲解：笔记 / 高亮 / 标注页怎么合成一条流

底下是**两张表**，各管一件事：

- `highlights` —— 一段有颜色的范围。
- `notes` —— 一段写下来的字。可以挂在书上（`scope: book`），
  也可以挂成跨书的（`scope: global`）。

`commands/annotations.rs` 把两张表 union 成一条按时间排的流，
并且把**指向同一个锚点**的一对折成一条。

**合并键是精确字符串相等**：`highlights.cfi_range` 对 `notes.location`，
外加 `book_id` 必须相同。这里**不解析锚点格式**——EPUB 是 CFI，纯文本是偏移量，
当作不透明字符串比就够了。所以两本书里碰巧出现同一个锚点字符串，仍然是两条。

界面上那排筛选（全部 / 高亮 / 有笔记的 / 词 / 选段 / 光高亮没笔记的）有个细节：
**计数是在「搜索 + 书 + 日期」筛完之后算的，但忽略类型筛选本身**。
这样切换类型时，你正在挑选的那排数字不会跟着变——否则每点一次，参照系就变一次。

结论：同一处既高亮又写了字，在标注页上是**一条**，不是两条。

## 八、讲解：复习那四个堆分别怎么算

前提：堆的**成员**只从 `vocab_words` 来（所以又回到第一节那道闸），
但堆的**理由**是从 `lookup_records` 和 `mastery_events` 里算的。
空堆自动消失；不设下限，1 个词也成堆。

### 堆 1 · 你在《X》里查了 N 次的词

每本书一堆。判据不是「同一个位置查了两次」，而是按 `(book_id, 词)` 把
`lookup_count` **加总 > 1**。

原因前面说过：`lookup_records` 对 `(book_id, cfi, normalized_text)` 有唯一索引，
所以「同一位置查 3 次」只是其中一种写法；「同一本书三个不同位置各查 1 次」
是同一个现象，而且信号更强。只看单行会漏掉后者。

堆里只有一个词时，会把总次数一起带出来，好让文案能写
「只有一个词，但你查了 4 次」——而不是为堆小而道歉。

### 堆 2 · 以为会了，结果又查了

条件很严，**两个都要**：

- 这个词 `mastery_events` 里**最新一条**是查词降级
  （`lookup_demotion` 或 `repeat_lookup_demotion`）；
- 并且**更早存在一条**曝光升级（`exposure_promotion`）。

意思是「引擎说你会了，你证明了它错」，而不只是「你查了个词」。
少了第二个条件，这堆会退化成「最近查过的词」，和堆 1、堆 3 撞车。

### 堆 3 · 刚读完的第 N 章里你查过这些

锚点是**全库最新的一条带章节的查词记录**。
**超过 24 小时，这堆就不存在**——它的全部价值在于「趁着还有印象」。

拿到锚点后，把那个 `(书, 章)` 里所有查过的生词捞出来。

### 堆 4 · 很久没再遇到的词

FSRS 兜底。`next_review_at` 已到期的词，**减去**已经出现在前三堆里的。

注意排他性只有这一条：**前三堆之间允许重叠**（一个词可以同时在两个行为堆里，
这是有意的），只有堆 4 是排他的。它永远排在最后，不管自己的时间戳多新——
因为它是唯一没有故事可讲的堆。
