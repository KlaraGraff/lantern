# 调研笔记：行业如何处理自相矛盾的用户信号

> 支撑「用户画像」设计中两个悬而未决的决策：修正信号怎么处理、主题结构要不要锁。
> 调研时间 2026-08-07，四路并行（短视频负反馈 / 显式vs隐式信号加权 / LLM 记忆系统 / 负例堆积失败模式）。
> 来源分级：**官方**（公司工程博客、论文、源码）/ **学术**（同行评审）/ **报道**（新闻调查）/ **社区**（逆向、传闻）。

## 一、短视频推荐器的负反馈机制

- **TikTok 的「不感兴趣」是临时性、会衰减的压制，不是永久拉黑。** 东北大学 2026 年学术审计（arXiv 2605.10690）实测：点了不感兴趣后，同类内容的出现率先降后回升。【学术】
- **YouTube 区分条目级（Not interested）和频道级（Don't recommend channel）两档。** 官方帮助文档只写作用范围，不写持续多久。【官方】Mozilla 的独立实验发现显式 dislike 的实际抑制效果只有约 11–12%，而屏蔽整个频道约 43%——平台对用户的显式负反馈给的权重比用户以为的低得多。【学术/独立研究】
- **行为与声明冲突时，YouTube 的公开论文（Zhao et al. 2019，多任务排序）用多目标损失加权解决，不存在「声明硬覆盖行为」的规则。**【官方论文】
- **没有任何平台公开「N 次行为 = 1 次显式声明」的换算比。** 这是设计决策，不是可引用的行业常数。
- 小红书基本无可靠公开资料，只有弱二手中文来源，不采信。

## 二、显式 vs 隐式信号加权、时间衰减

- **Netflix 把显式点赞和隐式行为并进同一个奖励函数**（play、complete、thumb 一起算），冲突场景（追了几周然后点踩、播 10 分钟弃剧的歧义）官方点名了但不公布解法。【官方 TechBlog】
- **Hu/Koren/Volinsky（ICDM 2008，经典论文）：隐式行为的「量」应该转成置信度（c = 1 + α·r），不是直接当偏好值。** 看得多 = 更确信这个判断，而不是 = 更喜欢。【学术】
- **Koren（KDD 2009）时间动态模型：用户偏好拆成慢漂移 + 单日尖峰两项**，还用「当天打分数量」这种隐式元数据去调节对显式打分的信任度。【学术】
- **时间衰减的学术参考值：半衰期约 150 天**（权重 = 0.5^(Δt/半衰期)，CEUR-WS Vol-2038，电影数据集）。生产系统的真实衰减常数无一家公开。【学术】

## 三、LLM 记忆系统的矛盾处理（信息量最大的一路）

- **ChatGPT Memory：矛盾靠「dreaming」——后台定期用 LLM 重写整个记忆态**，不在写入时同步问用户；用户手动改/删是事后兜底。OpenAI 自己的回顾承认旧版会出现「在备战马拉松」和「脚踝扭伤了」并存劣化个性化。dreaming 也不完全可靠，仍会产生并存的矛盾条目。【官方博客 + 报道】
- **mem0 的关键转向（对我们最有分量的一条）：** 2025 论文里著名的「LLM 判定 ADD/UPDATE/DELETE/NOOP」写入时裁决管线，在 2026 v3 被他们自己废弃了——改为只追加、永不删除、靠检索时排序（新近度+相关性）让「对的事实」浮上来。官方给的理由：写入时让 LLM 做 diff 既拖慢一倍延迟，又实测拉低准确率（LoCoMo 71.4→91.6 是砍掉裁决后涨的）。**一家生产厂商用真金白银从「写入时 LLM 裁决矛盾」上撤退了。**【官方文档 + 源码】
- **Zep/Graphiti：四个系统里唯一把矛盾处理写成完整机制的。** 双时间线模型：事实带「现实中何时为真」和「系统何时得知」两组时间戳；旧事实**永不删除，只标失效**（t_invalid = 新事实的 t_valid）；**矛盾检测只在同一对实体之间做**，不做全局比对；策略是「新信息优先」，但实现为带版本的过渡而非覆盖。【官方论文，直接引文核实】
- **arXiv 2606.01435（"Don't Ask the LLM to Track Freshness"）：** 让一次 LLM 调用同时负责过滤证据、压制过期信息、执行更新策略、生成答案，规模一大就崩（262K 上下文时准确率 75%→61%）。解法：**LLM 只做事实提取，矛盾/新近策略由确定性代码执行**。消融实验显示真正的收益来自「把提取和裁决分开」。【论文，数值按学术级置信对待】
- **四个系统没有一个在检测到矛盾时同步弹窗问用户**；全部自动处理、让用户事后检查修正。我们「删除/搬移即裁决」的显式动作路径在业界属于差异化设计。
- **公认的空白：** 没有系统把「情境化事实」当一等公民（「问事实题时要简洁」和「读小说时要展开」会被压成二选一的矛盾）。

## 四、负例/修正堆积的失败模式

- **退化反馈环**是推荐系统的正式术语（DeepMind AIES'19）：系统输出影响用户行为，行为又成为训练信号，闭环自我强化、越走越窄。【学术】
- **稀疏负反馈导致过度压制**（CHI 2025）：几次「不感兴趣」被错误泛化成整个类目的压制——正是「原始修正台账当负例喂」最像的翻车姿势。【学术】
- **Context rot**（Chroma 研究 + 从业者写作）：系统提示词里堆积的「别做 X」修正指令随长度增长劣化模型行为，矛盾指令互相打架，长上下文里有新近偏置。【独立研究/从业者】
- 直接把「LLM 画像总结器」正式当成推荐系统反馈环来分析的文献不存在——这个连接是我们自己的推理综合，非引用。

## 五、可迁移原则（设计依据）

1. **负反馈是带衰减的临时压制，不是永久拉黑。**（TikTok 审计、水位线哲学一致）
2. **显式动作当下压过推断行为，但显式也会过期；行为长期可以翻案。**（YouTube 权重实测、用户已裁决的「跟行为走」）
3. **存原始事件，喂派生状态。** 原始台账永不进提示词。（mem0 转向、context rot、2606.01435）
4. **矛盾裁决用确定性代码，LLM 只管提取和总结。**（2606.01435、mem0 撤退的教训）
5. **矛盾比对必须限定作用域（同槽位/同实体），需要稳定的键。**（Zep 的同实体对检测）
6. **永不硬删，标失效留历史。**（Zep 双时间线；对应我们的虚影卡 + 事件日志）
