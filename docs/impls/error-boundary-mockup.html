4 · 「重试」的三个状态

重试 = 用新的 key 重新挂载子树：组件 state 全部丢弃，effect 重跑，请求重发。 如果重挂之后立刻又崩，重试按钮就消失——继续给一个必然失败的按钮是在骗人。 这时只留「离开」类动作，并明说重试没有帮助。

静止 / idle

重挂载中 / pending — 不做

结论：边界不做等待态。重挂载是同步的，按下去当帧就换成了真正的面板； 要等的是面板自己的请求，那条骨架屏归它自己画。边界再转一个圈，只能是假的。 The boundary renders no pending state. The remount is synchronous — the real panel is back the same frame, and any waiting after that belongs to the panel's own loading skeleton. A spinner here could only be fake.

再次失败 / failed again

重试没有帮助，这个问题不会自己好。 Retrying didn't help — this one won't fix itself.

5 · 不出现在界面上的那一层

顶部通知（更新提示、AI 路由回退、生词回填公告）另有一个静默边界：它们崩了就消失， 不弹错误卡片。一个装饰性提示不该占住整块屏幕说自己坏了——但错误照样进 console 和磁盘日志。 这是既有约定的延伸：脚注模块加载失败也只记一条诊断然后继续。
